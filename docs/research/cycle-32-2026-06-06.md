# Cycle 32 - Raw Google OSS Archive Retention Policy

Date: 2026-06-06

## Objective

Decide whether `GOOGLE-OSS-RAW-INPUTS.zip` should remain attached to every
public tagged GitHub Release or only remain available as a workflow artifact
after the first validation window.

## Local Evidence

- `.github/workflows/release.yml` already creates `GOOGLE-OSS-RAW-INPUTS.zip`,
  includes it in `SHA256SUMS.txt`, mentions it in release notes, uploads it as a
  workflow artifact, and attaches it to tagged releases.
- `tools/release_artifact_bundle_check.py` already requires the archive in the
  release directory, checksum file, and release notes.
- `docs/distribution/supply-chain.md` told owners to inspect the archive but did
  not state whether public release retention was intentional and permanent.
- `docs/distribution/release-signing.md` under-described tagged release assets;
  it mentioned the APK and checksum file but not the notice/native artifacts.

## Source Review

Primary sources reviewed:

- GitHub workflow artifacts:
  `https://docs.github.com/en/actions/tutorials/store-and-share-data`
- GitHub releases and release assets:
  `https://docs.github.com/en/repositories/releasing-projects-on-github/about-releases`
- `actions/upload-artifact`:
  `https://github.com/actions/upload-artifact`
- `softprops/action-gh-release`:
  `https://github.com/softprops/action-gh-release`

GitHub's workflow artifact docs describe `retention-days` and repository,
organization, or enterprise retention limits. GitHub's release docs describe
release assets as part of deployable software iterations for a wider audience.
That makes workflow artifacts appropriate for dry-run review and release assets
the right home for evidence that should remain available with a public APK.

## Decision

Keep `GOOGLE-OSS-RAW-INPUTS.zip` attached to every tagged public Aura GitHub
Release that also publishes `THIRD-PARTY-NOTICES.md`.

## Implementation

Added `docs/distribution/raw-oss-input-retention.md` with:

- Decision date and retention rule.
- Rationale for permanent public release attachment.
- Enforced behavior in the release workflow and bundle validator.
- Change-control checklist if the policy changes later.
- Primary source references.

Updated:

- `.github/workflows/release.yml`
- `tools/release_artifact_bundle_check.py`
- `docs/distribution/supply-chain.md`
- `docs/distribution/release-dry-run.md`
- `docs/distribution/release-signing.md`
- `ROADMAP.md`
- `CHANGELOG.md`
- `COMPLETED.md`
- `AUTONOMOUS-LOOP-STATE.md`

## Verification

Executed locally:

```powershell
python -m py_compile tools\dependency_license_policy.py tools\dependency_overlay_check.py tools\dependency_notice_lock.py tools\google_oss_raw_archive.py tools\google_oss_to_markdown.py tools\native_compliance_inventory.py tools\release_artifact_bundle_check.py
python tools\dependency_notice_lock.py --mode check --lockfile docs\legal\dependency-notices.lock.json
python tools\native_compliance_inventory.py --mode check-lock --lockfile docs\legal\native-compliance.lock.json
python tools\dependency_overlay_check.py --overlay docs\legal\dependency-notice-overrides.json
python tools\dependency_license_policy.py --policy docs\legal\dependency-license-policy.json --overlay docs\legal\dependency-notice-overrides.json
```

Local release-bundle smoke tests proved:

- A bundle containing `GOOGLE-OSS-RAW-INPUTS.zip` passes the validator.
- A bundle missing `GOOGLE-OSS-RAW-INPUTS.zip` fails the validator.

## Result

Cycle 32 closes the raw notice input retention decision. Aura now explicitly
keeps the raw Google OSS input archive as a public tagged release asset and
continues to enforce that expectation in the release bundle validator.

## Remaining Risk

The next live release should still run a real manual GitHub Actions release dry
run once signing secrets are confirmed available. That owner-gated check should
archive the workflow run URL in the release docs.

rows and no generated notice browser inside the app.
