# Cycle 83 - Account Deletion Web Intake

## Scope

Define the private hosted web intake contract for users who cannot open Aura
and add a validator that converts raw form exports into redacted operator
receipts before request-code lookup.

## Sources

- Google Play account deletion requirements:
  https://support.google.com/googleplay/android-developer/answer/13327111
- Account deletion support flow:
  `docs/support/community-account-deletion.md`
- Cycle 82 completion receipt:
  `tools/community_account_deletion_completion_receipt.py`

## Local Evidence

- The in-app Settings flow can produce an `AURA-` request code, but Play also
  expects a web resource for users who uninstalled the app or cannot access it.
- Raw web form exports can contain requester contact data and free-text
  statements, so release/backend evidence needs a redacted receipt before any
  artifact is attached or archived.
- The existing lookup, plan, review, simulation, package, REST, and completion
  chain can consume the request code after a web intake receipt normalizes and
  validates the submission.

## Implementation

- Added `docs/support/community-account-deletion-web-intake.md` with required
  fields, the private export shape, validation command, and hosting notes.
- Added `tools/community_deletion_web_intake.py`.
- The validator requires a valid `AURA-` request code, requester contact,
  requester statement, support reference, allowed channel, and the three
  deletion/retention/public-upload attestations.
- The receipt hashes contact and requester statement fields, omits raw contact,
  statement text, full UIDs, RTDB paths, database exports, executor packages,
  and access tokens, and marks the request `readyForOperatorLookup`.
- Added `test/tools/community_deletion_web_intake_test.py` covering redaction,
  missing attestation rejection, and invalid request-code rejection.
- Wired the validator into Firebase backend CI change detection.
- Updated support, policy, runbook, roadmap, changelog, completed ledger, and
  loop state docs.
