# Cycle 87 - Account Deletion Upload Handoff Plan

## Scope

Add the private public-upload deletion handoff plan for deleted account requests
where the requester also asks support to remove owned public uploads.

## Sources

- Community upload deletion runbook:
  `docs/community-upload-deletion.md`
- Account deletion Auth package:
  `tools/community_account_deletion_auth_package.py`
- Existing upload deletion helpers:
  `app/src/main/java/com/freevibe/data/model/CommunityUploadOwnership.kt`

## Local Evidence

- Account deletion RTDB marker cleanup intentionally retains public upload
  metadata, owner indexes, and Storage objects until the owner/admin upload
  deletion workflow handles them.
- Cycle 86 creates the private Auth package with the full UID, but public upload
  deletion still needs a scoped list of owned sound/wallpaper uploads and rows
  that are blocked by missing or mismatched `storagePath` handles.
- Directly emitting destructive RTDB updates would be risky because Storage
  deletion, public metadata removal, owner-index removal, and tombstone writes
  must stay in lockstep.

## Implementation

- Added `tools/community_account_deletion_upload_plan.py`.
- Added `validate_auth_deletion_package()` to
  `tools/community_account_deletion_auth_package.py` for downstream private
  tooling.
- The upload plan validates the private Auth package, scans
  `community_sounds` and `community_wallpapers` for rows owned by the deleted
  UID, accepts rows with matching Storage prefixes, and blocks rows with missing
  or mismatched handles.
- Candidate rows include metadata path, owner-index path, deletion tombstone
  path, Storage path, content type, title, creation timestamp, and required
  owner/admin workflow text.
- The plan does not delete Storage objects or RTDB metadata.
- Added `test/tools/community_account_deletion_upload_plan_test.py` covering
  owned upload collection, blocked missing/wrong handles, ready status when all
  handles are present, and invalid Auth package rejection.
- Wired the upload plan tool into Firebase backend CI change detection.
- Updated support, policy, backend runbook, upload deletion runbook, roadmap,
  changelog, completed ledger, and loop state docs.
