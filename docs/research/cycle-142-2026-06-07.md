# Cycle 142 - Network Data Safety Surface Gate

## Scope

Cycle 142 expanded the checked Data safety matrix from manifest permissions to
reviewed network/provider surfaces. Owner-gated live callable evidence, hosted
deletion URL publication, production Firebase dry runs, GitHub security settings
evidence, signed release dry-run evidence, and fresh store screenshots remained
unavailable locally.

## Current Finding

Cycle 141 covered all manifest permissions, but the roadmap also requires SDK,
network destination, local store, diagnostics, and Firebase/community data-path
coverage. Aura already had a strong network endpoint inventory at
`docs/security/network-endpoints.json`; the missing piece was tying that
inventory to the privacy/Data safety source of truth.

## Implementation

- Added `networkEndpointInventory` and `networkSurfaces` rows to
  `docs/privacy/data-safety.json`.
- Added a Network Surface Ledger section to `docs/privacy/data-safety.md`.
- Extended `tools/privacy_data_safety_check.py` so every endpoint ID in
  `docs/security/network-endpoints.json` must have exactly one matching network
  Data safety row.
- Required data types, collection/sharing status, user control, retention, and
  deletion path for each network surface.
- Extended focused tests for missing and extra network surface rows.
- Updated release dry-run and supply-chain docs to describe the expanded gate.

## Verification

- `py -3 tools\privacy_data_safety_check.py --policy docs\privacy\data-safety.json --repo-root .`
- `py -3 -m unittest discover -s test/tools -p 'privacy_data_safety_check_test.py'`

## Remaining Work

- Add local-store, SDK, diagnostics, and Firebase data-path rows to the same
  Data safety source of truth.
- Build the Play app-content declaration packet using the manifest and network
  matrix as inputs.
- Capture fresh screenshots and a feature graphic before enabling store asset
  preflight mode.
