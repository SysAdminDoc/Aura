# Cycle 103 - Vote Callable Emulator Coverage

## Goal

Extend the RTDB-emulator-backed callable handler persistence lane from profile
edits and reports to community votes.

## Research

- `recordCommunityVote` writes a vote tally row under `/votes/{contentId}`,
  nested voter markers under `/votes/{contentId}/voters/{uid}`, legacy voter
  markers under `/voters/{contentId}/{uid}`, plus quota and dedupe ledgers.
- The focused Functions test already verifies content ID normalization,
  existing-voter idempotency, duplicate handling, cooldown, daily-limit, Auth,
  and App Check behavior using a fake backend.
- The wildcard emulator suite now covers multiple files that clear the shared
  RTDB emulator root, so the test runner should execute them serially.

## Implementation

- Added `test/firebase/functions.vote.test.mjs`.
- Updated `recordCommunityVoteHandler()` to default to its real Firebase Admin
  SDK backend when no fake backend is passed.
- Serialized `npm run test:functions-emulator` with
  `node --test --test-concurrency=1` so profile, report, and vote files do not
  race shared emulator cleanup.
- The vote emulator test verifies:
  - accepted vote writes under `/votes/{contentId}`;
  - nested and legacy voter markers for the authenticated UID;
  - quota rows under `/community_write_quotas/{uid}/{yyyyMMdd}/votes`;
  - dedupe markers under `/community_write_dedupe/{uid}/votes/{contentId}`; and
  - repeat-vote idempotency before additional quota mutation.
- Refreshed `docs/community-backend-manifest.json`.
- Updated roadmap, changelog, completed log, backend runbook, and loop state.

## Verification

- `npm run test:functions-emulator`
- `npm run test:functions`
- `py -3 tools\community_backend_manifest.py --mode check`
- `py -3 tools\community_callable_contract_check.py --contract docs\community-callable-contract.json`
- `npm --prefix functions audit --audit-level=high`
- `git diff --check`

## Remaining Risk

This is RTDB-emulator-backed handler persistence coverage, not a Firebase
callable wire-protocol test. Follows, blocks, sound uploads, and wallpaper
uploads still need the same persistence lane, and all surfaces still need full
callable protocol coverage, Android migration, owner-approved deploy evidence,
Firebase Console App Check evidence, and direct RTDB rule tightening.

## Next

- Add RTDB-emulator-backed handler persistence coverage for follows, user
  blocks, sound uploads, and wallpaper uploads.
- Add full callable wire-protocol coverage when Auth/App Check emulator wiring
  is available.
- Add Android callable adapters for reports, votes, follows, user blocks,
  upload metadata finalization, and profile edits.
