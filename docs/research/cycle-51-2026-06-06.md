# Cycle 51 - Community Report Queue Intake

## Scope

Cycle 51 implements the first report-intake and admin-resolution metadata slice
for community and mirrored provider content. It does not replace the existing
`/moderation/{contentId}` hide list; it adds the private report queue needed to
capture reason, reporter, source, license, and resolver context.

## Local Evidence

- `VoteRepository.moderateHide()` stored only `/moderation/{contentId}=true`.
- Detail screens had hide/downvote actions but no report flow for rights,
  source-removed, safety, spam, or other reasons.
- Cycle 50 added upload rights metadata, but there was no matching intake path
  for users or rights holders to flag those rows.
- `database.rules.json` had admin-only moderation writes but no private report
  read/write model.

## Implementation

- Added `CommunityReport.kt` with report reasons, resolution statuses, payload
  normalization, HTTPS source URL validation, and resolution payload validation.
- Added `CommunityReportRepository.kt` to submit private report records under
  `/community_reports/{reportId}` and write admin resolution metadata under
  `/community_report_resolutions/{reportId}`.
- Updated RTDB rules so authenticated users can create new report records,
  custom-claim admins can read/update them, and only admins can write
  resolution records.
- Added `CommunityReportDialog` with reason chips and optional details.
- Added report actions to sound and wallpaper detail screens.
- Updated `SoundsViewModel` and `WallpapersViewModel` to submit current content
  source, license, uploader, and HTTPS source URL context with each report.
- Added `docs/support/community-reporting.md` for report paths, privacy, and
  remaining admin workflow follow-up.
