# Cycle 74 - Account Deletion Dry-Run Planner

## Scope

Define and implement the first reviewable account deletion dry-run for
community identity marker data. This cycle intentionally does not add an
in-app delete button or trusted executor; it creates the deterministic plan
needed before either path can safely apply changes.

## Sources

- Google Play account deletion requirements:
  https://support.google.com/googleplay/android-developer/answer/13327111
- Firebase Realtime Database delete data:
  https://firebase.google.com/docs/database/android/read-and-write#delete_data
- Firebase Auth delete users:
  https://firebase.google.com/docs/auth/android/manage-users#delete_a_user
- Firebase Storage delete files:
  https://firebase.google.com/docs/storage/android/delete-files

## Local Evidence

- `VoteRepository.upvote()` writes per-user markers under both
  `/votes/{contentId}/voters/{uid}` and legacy `/voters/{contentId}/{uid}`.
- `CreatorProfileRepository.followCreator()` writes outbound follows under
  `/creator_follows/{uid}/{creatorId}`, and other users can follow a creator UID
  that later gets deleted.
- `CommunityBlockRepository` writes both outbound private block rows and
  admin-only reverse indexes.
- Public uploads need the existing owner/admin upload deletion workflow because
  metadata rows, owner indexes, Storage objects, and tombstones must stay in
  sync.

## Implementation

- Added `tools/community_account_deletion_plan.py`.
- The planner reads an exported RTDB JSON file plus a Firebase UID and emits a
  deterministic multi-path update object whose values are `null`.
- Planned deletions include nested vote markers, legacy vote markers, outbound
  and inbound follows, creator profile rows, outbound and inbound block rows,
  block reverse-index rows, and community share rows created by the UID.
- The planner explicitly retains aggregate vote counts, moderation/report audit
  roots, public upload metadata, owner indexes, and Storage objects with
  policy reasons.
- Added `test/tools/community_account_deletion_plan_test.py`.
- Updated backend CI change detection, Firebase harness docs, backend runbook,
  roadmap, changelog, completed ledger, and loop state.
