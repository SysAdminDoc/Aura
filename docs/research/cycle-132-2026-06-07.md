# Cycle 132 - Provider Key Clear UX

## Scope

Cycle 132 continued the local provider-key security follow-up by making stored provider key clearing explicit in Settings. Owner-gated live callable, hosted deletion URL, production Firebase, GitHub settings, and release-secret dry-run evidence remained unavailable locally.

## Local Evidence

- Cycle 130 documented that DataStore-backed provider keys can be cleared by saving blank values.
- Settings had separate API-key dialogs for Wallhaven, Pexels, Pixabay, Freesound, and Stability, each with Save and Cancel actions.
- The storage policy guard checked Settings labels, but did not prove an explicit clear affordance existed.

## Implementation

- Added a shared `ProviderApiKeyDialog` composable with Save, Clear, and Cancel actions.
- Swapped Wallhaven, Pexels, Pixabay, Freesound, and Stability Settings dialogs onto the shared dialog.
- Extended `tools/provider_credential_storage_check.py` and tests so the policy fails when the Settings provider-key clear action disappears.
- Updated provider credential storage docs, privacy copy, supply-chain docs, roadmap, changelog, completion, and loop state.
