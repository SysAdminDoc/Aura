# Cycle 94 - Community Report Callable Handler

## Goal

Implement the first real Cloud Functions write handler from the Cycle 63/91
callable quota contract while keeping production deploy and Android migration
explicitly gated.

## Research

- The repo's Android report payload builder requires server-derived reporter
  UID, uppercase content type/source/reason, HTTPS source URLs, bounded notes,
  and `OPEN` status.
- The RTDB rules for `/community_reports/{reportId}` validate the same public
  fields and keep report reads private to custom-claim admins.
- Firebase callable functions can enforce App Check and consume limited-use App
  Check tokens; the Cycle 91 manifest marks report submission as limited-use.
- The Cycle 93 Functions scaffold already exports all callable names and gives
  the report handler a stable Node 20/TypeScript test lane.

## Implementation

- Added `functions/src/reportHandler.ts`.
- Switched `submitCommunityReport` from fail-closed scaffold to
  `createSubmitCommunityReportCallable()`.
- The handler now:
  - requires Firebase Auth and App Check through the shared identity guard;
  - rejects client-supplied `reporterUid`;
  - validates the common envelope (`operationId`, `clientSentAt`, `payload`);
  - normalizes report fields to the Android/RTDB bounds;
  - requires HTTPS source URLs when present;
  - derives content-key/reason dedupe keys server-side;
  - reserves quota through the backend adapter using the UTC quota engine; and
  - writes the report and dedupe marker through a multi-location Admin SDK
    update after quota acceptance.
- Added `functions/test/submitCommunityReport.test.cjs` for accepted,
  duplicate, cooldown, daily-limit, unauthenticated, missing-App-Check,
  reporter-override, and insecure-source-URL paths.
- Refreshed `docs/community-backend-manifest.json` and updated reporting,
  quota, runbook, roadmap, changelog, completed log, and loop state docs.

## Verification

- `npm run test:functions`
- `py -3 tools\community_backend_manifest.py --mode check`
- `py -3 tools\community_callable_contract_check.py --contract docs\community-callable-contract.json`

## Remaining Risk

The report handler has focused Functions unit coverage, not a live Emulator
Suite invocation through the callable protocol. Production reliance still needs
emulator coverage, Android callable migration, owner-approved deploy evidence,
and Firebase Console App Check evidence.

- Implement the next handler-backed callable after reports have deploy evidence
