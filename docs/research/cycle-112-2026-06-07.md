# Cycle 112 Research - Android Sound Upload Finalizer Callable Migration

## Goal

Move Android sound upload metadata finalization from direct Realtime Database
first-write behavior to the existing `finalizeCommunitySoundUpload` callable
when Firebase Auth is available. Storage bytes still upload through Firebase
Storage; the callable owns the public metadata and owner-index write.

## Local Evidence

- `functions/src/soundUploadHandler.ts` accepts an envelope with `operationId`,
  `clientSentAt`, and sound metadata containing `name`, `category`, `tags`,
  `downloadUrl`, `storagePath`, `fileType`, `originalFileName`,
  `uploaderLabel`, `license`, `rightsAttested`, and optional `sourceUrl`.
- The backend derives uploader UID from Firebase Auth, requires App Check with
  limited-use token consumption, validates Storage path ownership, reserves
  quota, allocates the upload ID, writes `/community_sounds/{uploadId}` and
  `/owner_uploads/{uid}/sounds/{uploadId}`, and records a storage-path dedupe
  marker.
- `CommunityQuotaPolicies.soundUploads` maps sound uploads to
  `finalizeCommunitySoundUpload`, final writes public metadata plus owner
  index rows, and consumes limited-use App Check tokens.
- `UploadRepository.uploadSound()` already uploaded Storage bytes, fetched the
  download URL, and then wrote public metadata and owner-index rows directly to
  RTDB before Cycle 112.

## Implementation

- Added `CommunitySoundUploadMetadataInput` and
  `buildCommunitySoundUploadCallablePayload()` so Android sends only normalized
  finalizer metadata and omits server-owned uploader, timestamp, upload ID,
  public ID, and vote fields.
- Added `CommunityCallableClient.finalizeCommunitySoundUpload()` with
  `sound_upload_` operation IDs and limited-use App Check token selection.
- Updated `UploadRepository.uploadSound()` so the post-Storage metadata step:
  - Calls `finalizeCommunitySoundUpload` first when Firebase Auth has a current
    UID.
  - Treats `accepted` and `duplicate` callable responses as successful
    finalization.
  - Does not fall back to direct RTDB for quota, Auth, App Check, validation,
    storage ownership, or unexpected callable status failures.
  - Preserves the existing direct RTDB metadata and owner-index write only when
    the callable endpoint is missing or Firebase Auth is unavailable.
  - Keeps failed-finalization cleanup behavior that deletes the uploaded
    Storage object when metadata was not saved.
- Extended `CommunityCallableClientTest` for sound upload finalizer envelopes,
  metadata normalization, server-owned field omission, and limited-use token
  selection.
