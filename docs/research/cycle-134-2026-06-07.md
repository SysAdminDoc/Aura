# Cycle 134 - Generated Content Report Path

## Scope

Cycle 134 implemented the generated-content report/flag path for Aura's
generated wallpaper feature. Owner-gated live callable, hosted deletion URL,
production Firebase, GitHub settings, and signed-release dry-run evidence
remained unavailable locally.

## Policy Check

Google Play's AI-Generated Content policy covers image generation from text,
image, or voice prompts and requires apps that generate content using AI to
offer in-app user reporting or flagging for offensive content without requiring
users to leave the app. The policy overview also calls out offensive,
restricted, deceptive, and harmful generated-content categories for developer
moderation review.

## Implementation

- Added generated-content report reasons: Offensive, Unsafe, Deceptive, and
  Other.
- Let `CommunityReportDialog` accept an explicit reason set and body copy so
  community/provider reports keep existing categories while generated wallpapers
  use generated-content categories.
- Added a generated-content report action to the generated wallpaper result
  screen.
- Routed saved generated wallpaper favorites through the detail-screen report
  action with generated-content categories.
- Added a generated wallpaper report payload builder that omits Stability keys,
  other provider keys, local file paths, and prompt text unless the user writes
  prompt text in the note.
- Allowed `AI_GENERATED` wallpaper reports through `WallpapersViewModel` even
  when the Community source switch is off.
- Extended the Functions `submitCommunityReport` reason allowlist and focused
  backend test coverage for generated reports.
- Updated privacy/reporting docs, roadmap, changelog, completion, and loop
  state.
