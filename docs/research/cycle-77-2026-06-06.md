# Cycle 77 - Deletion Request Code Lookup

## Scope

Add the operator-side lookup needed after a user shares an `AURA-` community
deletion request code. The lookup maps a request code to candidate UID evidence
from a Realtime Database export without requiring users to publish full Firebase
UIDs.

## Sources

- Google Play account deletion requirements:
  https://support.google.com/googleplay/android-developer/answer/13327111
- Firebase Realtime Database export/deletion context:
  https://firebase.google.com/docs/database/android/read-and-write#delete_data
- Cycle 76 support route:
  `docs/support/community-account-deletion.md`
- Cycle 74 dry-run planner:
  `tools/community_account_deletion_plan.py`

## Local Evidence

- `CommunityDeletionRequest.kt` shares only the request code, identity suffix,
  and auth label.
- `tools/community_account_deletion_plan.py` still requires a UID before it can
  build a dry-run update plan.
- RTDB exports contain UID evidence in vote markers, creator profiles/follows,
  block lists/reverse indexes, owner upload indexes, reports, takedown receipts,
  and collection share ownership fields.

## Implementation

- Added `tools/community_deletion_request_lookup.py`.
- The tool validates `AURA-` request codes, collects UID candidates from
  known UID-bearing roots/fields, computes the same SHA-256 based request code,
  and emits matching UID evidence paths.
- Added `test/tools/community_deletion_request_lookup_test.py`.
- Wired the new tool into Firebase backend CI change detection.
- Updated the account deletion policy, support request doc, backend runbook,
  roadmap, changelog, completed ledger, and loop state.
