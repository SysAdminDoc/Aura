# Cycle 40 - Community Source Switch

Date: 2026-06-06

## Research

Aura's provider runtime-control matrix still listed Aura Community as missing a
real source-off mode. Community features are broader than a single tab: startup
identity warm-up, sound uploads, wallpaper uploads, vote counts, top-voted
wallpapers, creator profile dashboards, and creator follow state all touch
Firebase or community identity paths. A policy/offline distribution profile
therefore needs a first-class Community switch that is distinct from Firebase
outages or missing configuration.

## Local Evidence

- `FreeVibeApp.warmCommunityIdentity()` could create or refresh community
  identity state at startup before a user opened a community surface.
- `UploadRepository.kt`, `WallpaperUploadRepository.kt`, and
  `CreatorProfileRepository.kt` contacted Firebase independently.
- `SoundsScreen.kt` and `WallpapersScreen.kt` exposed Community tabs, upload
  actions, vote actions, and creator navigation without a runtime flag.
- Wallpaper detail and Discover vote-count paths could still read community
  vote data even when the source menu was not involved.

## Decision

Add a default-on `community_provider_enabled` preference so existing installs
keep current behavior, then guard every Firebase-backed community entry point
before identity, feed, upload, follow, or vote work starts. Disabled mode should
hide user actions and record `SourceMetrics` disabled events instead of
misclassifying operator disablement as a Firebase outage.

## Implementation

- Added a Community source switch in Settings and `PreferencesManager`.
- Skipped startup community identity warm-up when the switch is off.
- Guarded sound, wallpaper, and creator repositories before Firebase work.
- Hid community sound/wallpaper tabs, upload FABs, creator profile entry point,
  vote controls, and community vote-count reads while disabled.
- Added view-model defensive checks for stale tab selections, upload calls,
  recording calls, and community vote actions.
- Updated provider runtime-control docs to mark Community runtime disablement
  covered while keeping deletion, takedown, and App Check work separate.
