# Cycle 59 - Firebase Rules CI Gate

## Scope

Cycle 59 wires the local Firebase rules harness into GitHub Actions so RTDB and
Storage rules changes cannot bypass emulator verification.

## Implementation

- Added a `firebase-rules` job to `.github/workflows/verify.yml`.
- The job checks out with full history so it can compare the workflow base SHA
  to `GITHUB_SHA`.
- The job marks Firebase rules as changed when these paths move:
  - `database.rules.json`
  - `storage.rules`
  - `firebase.json`
  - `package.json`
  - `package-lock.json`
  - `test/firebase`
  - `docs/firebase-rules-harness.md`
  - `docs/firebase-admin-claims.md`
  - `.github/workflows/verify.yml`
- Manual workflow runs always execute the rules suite.
- When triggered, the job installs Java 17 for the Realtime Database emulator,
  installs Node 20 with npm cache, runs `npm ci`, and runs
  `npm run test:firebase-rules`.
