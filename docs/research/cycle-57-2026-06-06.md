# Cycle 57 - Storage Rules and Emulator Harness

## Scope

Cycle 57 adds the first tracked Firebase Storage rules and a local Emulator
Suite test harness for community upload blobs. This covers owner path
enforcement, MIME/size ceilings, delete authorization, public read behavior,
and closed unmanaged paths.

## Primary Sources

- Firebase Security Rules for Cloud Storage: https://firebase.google.com/docs/storage/security
- Cloud Storage Security Rules reference: https://firebase.google.com/docs/reference/security/storage
- Firebase Security Rules unit testing: https://firebase.google.com/docs/rules/unit-tests
- Emulator Suite rules-unit-testing reference: https://firebase.google.com/docs/reference/emulator-suite/rules-unit-testing/rules-unit-testing

## Local Evidence

- Cycle 9 and Cycle 12 both found that Aura had `database.rules.json` but no
  tracked `firebase.json`, `.firebaserc`, `storage.rules`, or rules test
  harness.
- Sound uploads write `sounds/{uid}/{timestamp}_{name}.{ext}` and allow local
  files up to 20 MB.
- Wallpaper uploads write `wallpapers/{uid}/{timestamp}_{name}.jpg`, compress to
  JPEG, and cap local uploads to 4 MB.
- Cycle 55 added canonical `storagePath` metadata, and Cycle 56 added visible
  owner delete actions that rely on Storage delete authorization matching app
  behavior.

## Implementation

- Added `firebase.json` mapping `database.rules.json` and `storage.rules`, plus
  a Storage emulator port.
- Added `storage.rules` with owner-only creates under `sounds/{uid}` and
  `wallpapers/{uid}`, public reads, owner/admin deletes, blocked overwrites, and
  closed fallback paths.
- Added a project-local npm harness with pinned `@firebase/rules-unit-testing`,
  `firebase`, and `firebase-tools` dev dependencies plus `package-lock.json`.
- Added `test/firebase/storage.rules.test.mjs` using Node's built-in test runner
  to exercise owner creates, cross-owner rejection, anonymous rejection,
  wrong-MIME rejection, oversize rejection, owner delete, admin delete, public
  download URL reads, and unmanaged path denial.
- Added `/node_modules` to `.gitignore`.
- Added `docs/firebase-rules-harness.md` with local verification, policy, audit,
  and remaining work notes.

## Verification

The first pass also passed but logged a rules evaluation warning when checking
`request.auth.token.admin` for non-admin tokens. `storage.rules` now guards the
custom claim with `'admin' in request.auth.token`, and the rerun passed without
rules-evaluation warnings.

Additional check:

```powershell
npm audit --audit-level=moderate
```

The audit currently fails on a moderate transitive `uuid` advisory through
`firebase-tools` -> `gaxios`. npm only offers a forced downgrade to
`firebase-tools@13.13.3`; this cycle documents the dev-test-tool risk instead
of downgrading the current emulator CLI pin.
