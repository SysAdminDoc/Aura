# Cycle 42 Research: Wallhaven Source Switch

## Goal

Close the Wallhaven full-source runtime-control gap so distribution profiles can
remove Wallhaven entirely without relying only on a blank API key or SafeSearch
coercion.

## Local Evidence

- `WallpaperRepository` used Wallhaven for featured/toplist browsing, direct
  search, similar lookup, random wallpapers, color search, Discover primary
  loading, and style-biased Discover loading.
- `WallpapersViewModel` exposed Wallhaven as a top-level wallpaper tab and used
  Wallhaven-backed color/random/similar actions from route filters, detail
  actions, Theme Match, EyeDropper, and Surprise Me.
- `AutoWallpaperWorker` supported `"wallhaven"` as both legacy and scheduled
  rotation source.
- Settings source pickers always offered Wallhaven, and Discover cached previews
  could briefly show stale Wallhaven rows before network refresh completed.
- `ProviderDisclosure.kt` and `docs/legal/provider-runtime-controls.md` marked
  Wallhaven as `Partial` because the optional API key did not disable public
  SFW calls.

## Decision

Add a default-on `wallhaven_provider_enabled` preference. The switch blocks
Wallhaven at the repository boundary before key reads, cache fallback, or
Retrofit calls, while keeping saved legacy records renderable outside active
feed paths.

## Implementation Notes

- `PreferencesManager` now stores `wallhaven_provider_enabled` and exposes a
  setter.
- Settings now shows an `Enable Wallhaven source` switch and hides Wallhaven
  from legacy/scheduled rotation pickers when disabled, while preserving stale
  selected values so users can change them.
- `WallpaperRepository` now returns empty disabled-source results for featured,
  random, color, similar, search, and Discover Wallhaven calls when disabled.
- `WallpapersViewModel` now redirects disabled Wallhaven tab selections, blocks
  Wallhaven-only color/random/similar actions with a source-specific message,
  and filters Wallhaven rows from cached Discover previews while the flag is
  off.
- `WallpapersScreen` hides the Wallhaven tab plus Theme Match, EyeDropper, and
  Surprise Me actions when Wallhaven is disabled.
- `AutoWallpaperWorker` exits successfully for disabled scheduled or legacy
  Wallhaven rotations after invoking the repository guard, avoiding retry loops.

## Verification Plan

- Focused repository test proves disabled Wallhaven records a disabled
  diagnostic and never calls the Wallhaven API.
- Focused Wallpapers view-model test proves the disabled tab redirects and
  Wallhaven-only actions do not call the repository.
- Focused Settings and provider disclosure tests verify the new preference flow
  and covered runtime-control row.
- Release-compliance Python checks remain unchanged and should still pass.
