# Cycle 69 - Public Takedown Copy

## Scope

Cycle 69 adds visible public-listing and takedown expectation copy to Aura's
community upload, report, and owner-delete flows. The change is intentionally
client-side and policy-facing: it does not change Firebase rules, upload
schemas, or admin deletion behavior.

## Primary Sources

- Google Play User Generated Content policy:
  https://support.google.com/googleplay/android-developer/answer/9876937
- Google Play moderation requirements for UGC apps:
  https://support.google.com/googleplay/android-developer/answer/12923286

## Local Evidence

- Community sound and wallpaper uploads already require license selection,
  rights attestation, optional HTTPS source URL, public metadata writes, owner
  delete handles, private reports, admin takedown receipts, and confirmed admin
  deletes.
- The upload dialogs did not yet say that the listing becomes public or that
  confirmed rights reports can hide/delete the upload.
- The report dialog offered a `Rights or license` reason but did not explain
  that it is the takedown route or that reports stay private to admins.
- Owner-delete confirmations only mentioned removing the media file, not the
  public listing, owner index, or retained private moderation records.

## Implementation

- Added `CommunityPolicyCopy.kt` with content-specific upload disclosure,
  attestation, report, and owner-delete confirmation copy.
- Added `CommunityPolicyNotice` for rectangular policy notices in Compose
  dialogs.
- Updated sound and wallpaper upload dialogs to disclose public listing
  behavior, stored license/source/uploader/tag metadata, and confirmed
  rights-takedown outcomes before attestation.
- Updated the shared community report dialog with rights-takedown and private
  admin-review copy.
- Updated sound and wallpaper owner-delete confirmations to describe public
  metadata/index removal and private retention of deletion/takedown records.
- Added focused JVM tests for the reusable policy copy.
