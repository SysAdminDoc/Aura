# Cycle 139 - On-device Wallpaper Decision Gate

## Scope

Cycle 139 converted the on-device wallpaper generation follow-up into a checked
decision gate. Owner-gated live callable evidence, hosted deletion URL
publication, production Firebase dry runs, GitHub security settings evidence,
signed release dry-run evidence, and fresh store screenshots remained
unavailable locally.

## Current Finding

On-device generation is promising but not ready for Aura's shipped wallpaper
flow. Local Dream shows Android Stable Diffusion can use Snapdragon NPU paths,
but its current support matrix is narrow. Qualcomm demos show strong best-case
latency on recent Snapdragon hardware, while LiteRT's current Android/NPU docs
still require per-vendor runtime handling, dynamic delivery planning, and
CPU/GPU fallback decisions. Android AICore/Gemini Nano has useful local
privacy/safety properties, but it is not an image-generation API replacement
for Aura's wallpaper feature.

## Implementation

- Added `docs/ai/on-device-wallpaper-decision.json` and
  `docs/ai/on-device-wallpaper-decision.md`.
- Set the current decision to `hold` and kept Stability BYO-key generation as
  the only supported generation path.
- Required evidence categories for device baseline, model size/storage,
  latency/battery/thermal behavior, license redistribution, moderation and
  reporting, fallback/user choice, and FOSS-channel impact.
- Added `tools/on_device_ai_decision_check.py` to validate the packet and scan
  production build/source paths for early on-device runtime dependencies or
  model artifacts while the decision is not approved.
- Added focused backend tests for the live packet, missing criteria, non-HTTPS
  sources, premature approval, missing evidence references, forbidden runtime
  dependencies, model artifacts, and fallback drift.
- Wired the guard into `.github/workflows/verify.yml`.
- Updated generated wallpaper privacy docs so release review keeps local
  generation disabled unless the decision gate is approved.

## Verification

## Remaining Work

- Collect real-device latency, battery, thermal, cancellation, and storage
  evidence before any prototype moves toward production.
- Complete model and runtime license review before bundling or downloading any
  local generation artifact.
- Decide FOSS-channel handling if Play AI Packs, vendor runtimes, or
  proprietary model artifacts become required.
- Keep hosted Stability BYO-key mode as the fallback until all criteria are met.
