# Cycle 55 - Community Upload Deletion Handles

## Scope

Cycle 55 starts the owner-delete/takedown roadmap by making new community sound
and wallpaper uploads carry canonical deletion handles. This cycle stores
Storage paths, writes private owner indexes, adds repository owner-delete
methods, and documents the remaining UI/admin/backfill work.

## Primary Sources

- Google Play account deletion requirements: https://support.google.com/googleplay/android-developer/answer/13327111
- Firebase Realtime Database Android delete data: https://firebase.google.com/docs/database/android/read-and-write
- Firebase DatabaseReference API: https://firebase.google.com/docs/reference/android/com/google/firebase/database/DatabaseReference
- Firebase Storage Android delete files: https://firebase.google.com/docs/storage/android/delete-files

## Local Evidence

- Cycle 12 found that community uploads stored public download URLs but no
  canonical `storagePath`, forcing deletion plans toward brittle URL parsing.
- `UploadRepository.uploadSound()` and `WallpaperUploadRepository.uploadWallpaper()`
  already know the Storage object path before writing RTDB metadata.
- `database.rules.json` already authorizes owner/admin writes to community upload
  metadata through `uploaderUid`, but it had no private owner upload index.
- The repo has no tracked Storage rules yet, so this cycle cannot honestly claim
  end-to-end Storage-rule enforcement.

## Implementation

- Added `CommunityUploadOwnership.kt` with upload-kind metadata, sanitized public
  metadata paths, private owner-index paths, owner-index payloads, and
  multi-location delete update builders.
- Added `CommunityUploadDeletionHelpers.kt` so repositories can delete a Storage
  object by canonical path and treat already-missing objects as removable.
- Updated sound and wallpaper upload repositories to store `storagePath` in
  public metadata and atomically write `/owner_uploads/{uid}/...` rows alongside
  the public upload row.
- Added `deleteSoundUpload(uploadId)` and `deleteWallpaperUpload(uploadId)` owner
  methods that require matching `uploaderUid`, require `storagePath`, delete the
  Storage object, and remove public metadata plus owner index.
- Updated `database.rules.json` to validate new `storagePath` fields and protect
  `/owner_uploads` so only the owner or custom-claim admins can read/write index
  rows.
- Added `docs/community-upload-deletion.md` with current behavior and remaining
  UI/admin/backfill work.
