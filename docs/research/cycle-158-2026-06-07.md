# Cycle 158 research - support bundle live receipts

## Goal

Merge the live background-work diagnostics snapshot into the copied crash and
support bundle so issue reports include the same local evidence shown in
Settings.

## Local evidence

- Cycle 155 added an inferred background-work support section to
  `CrashDiagnosticsCollector`.
- Cycle 156 added `BackgroundWorkDiagnosticsReader` for live WorkInfo and
  Data Saver receipts.
- Cycle 157 added `BackgroundWorkReceiptStore` and worker last-run receipts.
- The crash/support bundle is copied or shared only after explicit user action,
  and the existing redaction layer already removes provider credentials,
  private app paths, and file URIs from crash logs.

## Implementation decision

`CrashDiagnosticsCollector` now reads `BackgroundWorkDiagnosticsReader` during
bundle generation and appends a `Background work live receipts` section when
the read succeeds. The live section includes:

- active metered/unmetered network state;
- Data Saver restricted-background status;
- WorkInfo state summary, record count, and max attempts for each unique work;
- persisted last result, success/failure timestamps, error class, and deferral
  reason.

The reader failure path is intentionally non-fatal. The original static
background-work support context remains present even if live receipts cannot be
read.
