# Cycle 136 - Generated Request Cost Guardrails

## Scope

Cycle 136 closed the generated wallpaper credit, rate-limit, and duplicate
request guardrail item. Owner-gated live callable evidence, hosted deletion URL
publication, production Firebase dry runs, GitHub security settings evidence,
and signed release dry-run evidence remained unavailable locally.

## Research

Stability's current platform pricing page says API usage is credit-based and
pricing can change as models and infrastructure change. The current API
reference documents 429 rate limiting with a 60-second timeout path. Aura
already mapped 402 and 429 errors after a provider response, but the UI did not
show local request count evidence, and the ViewModel could still cancel and
restart an active request if called directly while a paid generation was
already running.

## Implementation

- Added a ViewModel-level in-flight generation guard so direct duplicate calls
  are rejected before canceling or replacing an active Stability request.
- Added a local session request count to the generated wallpaper UI.
- Added same prompt/style duplicate detection after a successful generation and
  a confirmation dialog before sending another matching Stability request.
- Updated the generated wallpaper disclosure to mention changing pricing and
  rate limits.
- Tightened 402 and 429 copy to point users to the Stability account page and
  cooldown action instead of implying automatic retry.
- Updated `docs/privacy/ai-generation.md` with the credit/rate-limit/duplicate
  request behavior and release checklist rows.
