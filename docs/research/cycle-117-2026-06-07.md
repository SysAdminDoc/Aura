# Cycle 117 Research - GitHub Security Workflow Policy Guard

## Goal

Add a checkable repository policy that keeps Aura's GitHub security and
release workflows aligned with the documented supply-chain controls while
owner-gated live callable rollout evidence remains unavailable.

## Local Evidence

- Cycle 116 left live callable invocation proof, deploy evidence, App Check
  console evidence, and direct RTDB rule tightening open pending owner access.
- `.github/workflows/dependency-review.yml` is the pull-request dependency
  vulnerability gate.
- `.github/workflows/scorecard.yml` is the OpenSSF Scorecard and SARIF upload
  gate.
- `.github/workflows/release.yml` is the signed APK, checksum, release bundle,
  and attestation gate.
- `docs/distribution/supply-chain.md` already lists these controls, but the
  workflow-specific trigger, permission, attestation, and unsafe escape-hatch
  expectations were not machine-checked by a repo-local policy.

## Implementation

- Added `docs/distribution/github-security-workflows.json` as the reviewed
  workflow policy for Dependency Review, OpenSSF Scorecard, and Release.
- Added `tools/github_security_workflow_check.py` to validate policy metadata,
  unique workflow names and paths, required workflow snippets, missing workflow
  files, and forbidden snippets.
- The policy pins Dependency Review to pull requests, read-only contents,
  pull-request comments, `actions/dependency-review-action@v5`,
  high-severity failure, and always-on PR summaries while forbidding
  `pull_request_target` and writable contents.
- The policy pins Scorecard to branch-protection, push, schedule, and manual
  triggers, read-only checkout credentials, SARIF generation/upload, disabled
  public result publishing, and CodeQL SARIF upload while forbidding
  `pull_request_target` and persisted checkout credentials.
- The policy pins Release to tag/manual triggers, artifact attestation,
  checksum-based subjects, release bundle checks, Google OSS raw inputs,
  release uploads, and required write permissions while forbidding
  `pull_request_target` and dependency-verification suppression.
- Added `test/tools/github_security_workflow_check_test.py` for the live policy
  and negative drift cases around missing required snippets, forbidden
  snippets, duplicate names, duplicate paths, and missing workflow files.
- Wired `.github/workflows/verify.yml` to run the policy check in the always-on
  verify job before Android setup.
- Updated `docs/distribution/supply-chain.md`, `ROADMAP.md`, `COMPLETED.md`,
  `CHANGELOG.md`, and loop state with the new guard.

## Remaining Risk

- This cycle guards checked-in workflow configuration; it does not prove that
  GitHub branch protection or repository security settings are configured in
  the live GitHub project.
- Live callable production claims still require owner-approved deploy evidence,
  Firebase Console App Check evidence, valid private invocation evidence for
  all seven callables, and direct RTDB rule tightening.
