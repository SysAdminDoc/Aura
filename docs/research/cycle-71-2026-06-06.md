# Cycle 71 - Visible Block Creator Actions

## Scope

Cycle 71 adds the first user-visible block entry points for community content.
Community sound and wallpaper detail surfaces now expose confirmed `Block
creator` actions when the item carries a community uploader identity.

## Primary Sources

- Google Play User Generated Content policy:
  https://support.google.com/googleplay/android-developer/answer/9876937
- Google Play moderation requirements for UGC apps:
  https://support.google.com/googleplay/android-developer/answer/12923286
- Firebase Realtime Database Android read/write documentation:
  https://firebase.google.com/docs/database/android/read-and-write
- Firebase Realtime Database Security Rules:
  https://firebase.google.com/docs/database/security

## Local Evidence

- Cycle 68 reserved private block-list and admin reverse-index paths.
- Cycle 70 added `CommunityBlockRepository` plus feed/profile filtering, but no
  visible UI entry point could trigger a block write.
- Community detail screens already exposed report and owner-delete actions, so
  they were the smallest trusted surface for a confirmed block action.
- The existing `Sound` and `Wallpaper` models carried uploader display names but
  not the canonical community uploader ID needed for block writes.

## Implementation

- Added optional `communityUploaderId` metadata to `Sound` and `Wallpaper`.
- Populated `communityUploaderId` from community sound and wallpaper metadata
  using canonical `uploaderUid` with legacy `uploaderId` fallback.
- Added reusable block confirmation copy that explains private account-level
  hiding and no uploader notification.
- Added `SoundsViewModel.blockCommunitySound()` and
  `WallpapersViewModel.blockCommunityWallpaper()` using
  `CommunityBlockRepository.blockUser(..., CommunityBlockReason.OTHER)`.
- Successful block writes now remove matching normalized uploader rows from the
  current sound feed, community upload cache, wallpaper feed, and top-voted
  wallpaper rows.
- Added confirmed `Block creator` actions to `SoundDetailScreen` and
  `WallpaperDetailScreen`. The actions are hidden for non-community content,
  missing uploader identities, and owner-deletable uploads.
