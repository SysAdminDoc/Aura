# Cycle 56 - Visible Owner Delete Actions

## Scope

Cycle 56 completes the app-visible owner delete slice for new community sound
and wallpaper uploads. Cycle 55 added canonical `storagePath` handles and
repository delete methods; this cycle adds owner-gated availability probes,
ViewModel delete entry points, detail-screen confirmation actions, and focused
coverage.

## Primary Sources

- Google Play account deletion requirements: https://support.google.com/googleplay/android-developer/answer/13327111
- Firebase Realtime Database Android delete data: https://firebase.google.com/docs/database/android/read-and-write
- Firebase DatabaseReference API: https://firebase.google.com/docs/reference/android/com/google/firebase/database/DatabaseReference
- Firebase Storage Android delete files: https://firebase.google.com/docs/storage/android/delete-files

## Local Evidence

- Community sound UI rows use public IDs with a `cu_` prefix, and community
  wallpaper UI rows use public IDs with a `cw_` prefix; the existing
  `sanitizeCommunityUploadKey()` helper normalizes both forms back to Firebase
  upload keys.
- `SoundDetailScreen.kt` already has a report action area suitable for a
  direct owner delete button.
- `WallpaperDetailScreen.kt` already routes secondary actions through the
  More sheet, which is the least disruptive place for a destructive upload
  action.
- The repository delete methods from Cycle 55 already remove Storage objects
  and metadata but had no safe UI availability check.

## Implementation

- Added `canDeleteSoundUpload()` and `canDeleteWallpaperUpload()` repository
  probes that require a matching signed-in owner and a nonblank `storagePath`.
  Legacy rows or cross-owner rows fail closed and do not show delete UI.
- Added `canDeleteCommunitySound()` / `deleteCommunitySound()` to
  `SoundsViewModel`.
- Added `canDeleteCommunityWallpaper()` / `deleteCommunityWallpaper()` to
  `WallpapersViewModel`.
- Added an owner-only `Delete upload` button and confirmation dialog to the
  sound detail screen.
- Added an owner-only `Delete upload` action and confirmation dialog to the
  wallpaper detail More sheet.
- Updated the community upload deletion runbook with the Cycle 56 visible
  action behavior and the remaining admin/backfill/Storage-rules work.
