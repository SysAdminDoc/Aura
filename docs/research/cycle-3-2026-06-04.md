# Project Research and Feature Plan

**Project:** Aura (`com.freevibe`)
**Cycle:** 3
**Date:** 2026-06-04

## Executive Summary

Cycle 3 focused on provider compliance, source resilience, and source-specific kill switches. Aura aggregates wallpaper, video, and sound content from multiple providers. That breadth is the product's advantage, but official provider terms create several implementation requirements that are not yet expressed as a provider-by-provider runtime contract.

Roadmap handoff: Cycle 3 queue items were appended to `ROADMAP.md` after the implementation lane cleared its roadmap edits.

Top findings:

- P0: Pexels is the highest compliance risk because its API guidance explicitly rejects standalone wallpaper/image-gallery replication. Aura should keep Pexels only as an enhancement behind a provider compliance matrix and kill switch.
- P1: Pixabay requires result attribution, 24-hour request caching, rate-limit header handling, and no permanent image hotlinking. Aura should encode those as source policy, not tribal knowledge.
- P1: YouTube extraction remains a high-risk feature because Aura uses NewPipe/yt-dlp to search, resolve, cache, and download audio/video streams. It needs a legal-mode/off switch and non-YouTube fallback defaults.
- P1: Freesound and SoundCloud have source-specific licensing, attribution, and API-usage constraints. Aura needs a license capability matrix that gates trimming, downloading, applying, caching, and sharing.
- P2: Reddit source use needs app-review/rate-limit/removal handling and a better takedown path for source-deleted content.

- Pexels API guidance says the API is not for replicating Pexels or creating similar competing wallpaper/image gallery apps, while allowing background selection when it enhances a product with a different primary purpose.
- Pixabay API docs request source visibility in search results, document a default 100 requests per 60 seconds, require request caching for 24 hours, prohibit permanent image hotlinking, and return 429 on rate-limit errors.
- Freesound API terms state free API use is non-commercial, warn not to replicate Freesound or present its data as your own, require proper credit according to each sound license, and require reasonable API use without key circumvention.

Aura's NewPipe/yt-dlp path may not be using official YouTube API credentials, but it still creates distribution and policy risk that must be planned explicitly.

## Findings

### Pexels must be treated as an enhancement source, not core wallpaper inventory

Pexels is a direct fit for background image selection, but its official API help page rejects apps whose core experience is serving images for download as wallpapers. Aura is broader than a Pexels clone, but Wallpapers and Videos are first-class tabs and Pexels appears in those feeds.

Planning implication: ship a provider compliance matrix and a Pexels kill switch before increasing Pexels prominence, bundled defaults, or auto-rotation from Pexels. The safe direction is "Pexels enhances search/style matching" rather than "Pexels powers Aura's wallpaper catalog".

### Pixabay needs explicit cache, attribution, and hotlink behavior

Pixabay exposes useful metadata and has permissive media, but its API docs set operational rules: show users where search results come from, cache requests for 24 hours, honor rate-limit headers, avoid lots of automated queries, and do not permanently hotlink images.

Planning implication: encode provider rules in one `ProviderPolicy` contract: attribution required in search/result/detail, API response cache TTL, media URL cache/download TTL, hotlink allowance, mass-download guard, and rate-limit header handling.

### YouTube extraction needs a legal-mode fallback

Aura's YouTube sounds and video-wallpaper paths are valuable, but local code uses NewPipe/yt-dlp to scrape, resolve streams, cache stream URLs, and download audio/video. Official YouTube API policy is restrictive around undocumented APIs, downloading/caching/storing content, offline playback, and background playback.

Planning implication: add a "YouTube legal mode" decision before deeper YouTube expansion. At minimum: a global kill switch, per-distribution default, source-health warning, no YouTube as a required first-run/default source, issue-template guidance, and fallback discovery through Freesound/Audius/ccMixter/community sources.

### Sound provider licenses need action-level gating

Aura already displays license/uploader badges for sounds, but application behavior needs to be gated by license and provider terms. Freesound requires credit according to each sound's license and free API use is non-commercial. SoundCloud requires uploader/source attribution and has strong restrictions around copying, ripping, modifying, and using user content outside uploader permissions.

Planning implication: add action-level license capabilities: preview, trim, normalize, download, set as ringtone/notification/alarm, share, include in Aura Originals, and use in any generator/training workflow. Each source should declare which actions are allowed and which require user confirmation or are disabled.

### Reddit needs deletion and takedown handling

Aura maps Reddit permalinks and authors into local models, but Reddit's developer terms reserve app review and require handling deleted/removed/suspended/protected content. If Aura stores or caches Reddit media for video wallpapers, it needs removal behavior and source-deleted state.

Planning implication: add source-deletion reconciliation for Reddit and other user-generated sources: when detail reload fails or source content disappears, stop surfacing it as live catalog content, keep local favorites only with a clear unavailable/source-deleted state, and expose report/removal paths.

## Roadmap-ready Queue

The following items were appended to `ROADMAP.md` in the Cycle 3 researcher queue.

- [ ] P0 - Provider compliance matrix and runtime kill switches
  - Why: Pexels, Pixabay, Freesound, SoundCloud, Reddit, and YouTube each impose different attribution, caching, rate-limit, download, and deletion rules. Aura currently stores some metadata but does not encode provider policy centrally.
  - Evidence: Pexels wallpaper-app restriction; Pixabay 24-hour cache/rate-limit/hotlinking rules; Freesound non-commercial/credit/fair-use API terms; SoundCloud attribution and no-ripping restrictions; Reddit app-review/removal terms; YouTube undocumented/download/cache restrictions.
  - Touches: provider repositories, `SourceMetrics`, Settings provider toggles, detail screens, downloader/apply flows, docs/legal/provider-policy.md.
  - Acceptance: every provider has a policy row covering attribution, source link, API cache TTL, media cache TTL, hotlinking, download/apply/share allowances, rate-limit handling, deletion behavior, and kill-switch default.
  - Verify: provider policy unit tests; Settings can disable each remote provider; disabled providers vanish from search/default feeds; existing favorites retain source-deleted/unavailable state without crashing.

- [ ] P1 - Pexels usage guardrail and fallback plan
  - Why: Pexels specifically rejects standalone wallpaper/gallery API replication. Aura must prove Pexels is an enhancement source, not the product's core inventory.
  - Evidence: Pexels API wallpaper-app guidance; Aura uses Pexels in wallpaper/video discovery and style-biased feeds.
  - Touches: wallpaper/video source weights, onboarding defaults, provider copy, source detail attribution, fallback source selection.
  - Acceptance: Pexels is not the sole or default required source for any first-run flow; Pexels results always show source/creator context in search/detail; provider can be disabled remotely/configurably without breaking feeds; docs explain the allowed enhancement use case.
  - Verify: turn off Pexels and run Wallpapers/Videos first-run; source badges/links visible; no auto-rotation defaults depend only on Pexels.

- [ ] P1 - Provider cache and rate-limit policy engine
  - Why: Pixabay and Freesound have explicit cache/rate-limit expectations, but Aura's rate-limit handling is currently host-specific and policy-free.
  - Evidence: `RateLimitInterceptor.kt` targets Freesound; Pixabay docs require 24-hour request caching and expose rate-limit headers; `SourceMetrics.kt` records failures but does not enforce provider rules.
  - Touches: `RateLimitInterceptor`, provider repositories, cache metadata, `SourceMetrics`, Settings diagnostics.
  - Acceptance: provider policies declare request cache TTL, media URL TTL, Retry-After handling, max automatic prefetch, and mass-download guard; Settings source-health view shows quota/cache state where available.
  - Verify: simulated 429 with Retry-After for Pixabay/Freesound; cache hit avoids duplicate request inside TTL; mass-download guard blocks batch prefetch beyond policy.

- [ ] P1 - YouTube legal-mode/offline-risk switch
  - Why: Aura's YouTube feature set searches, resolves, caches, and downloads audio/video through NewPipe/yt-dlp, while YouTube's official policy is restrictive around undocumented access, downloads, caching, offline playback, and background playback.
  - Evidence: `YouTubeRepository.kt` NewPipe/yt-dlp stream extraction; `VideoWallpapersViewModel.kt` yt-dlp download path; YouTube API developer policies.
  - Touches: YouTube repository abstraction, Sounds YouTube tab, video wallpaper YouTube source, Settings provider toggles, distribution docs, issue templates.
  - Acceptance: distributor can disable YouTube features; first-run does not require YouTube; UI clearly labels YouTube as optional; fallback sources remain useful; no YouTube download/cache happens when legal mode disables it.
  - Verify: disable YouTube and run Sounds/Videos; Freesound/Audius/ccMixter/community paths still work; source metrics record disabled state separately from provider outage.

- [ ] P1 - Sound license capability gates
  - Why: Licenses and provider terms differ by source and action. A badge alone is not enough to decide whether a sound can be trimmed, normalized, downloaded, set as a ringtone, shared, or bundled.
  - Evidence: `SoundDetailScreen.kt` displays license/uploader metadata; Freesound and SoundCloud terms require source-specific credit and usage compliance.
  - Touches: sound models, sound repositories, editor/apply/share flows, Aura Originals curation, licenses screen.
  - Acceptance: each sound has normalized license metadata and action capabilities; restricted actions are disabled or require confirmation; Aura Originals accepts only reviewed CC0/compatible assets; source link/uploader/license appear in every detail/export path.
  - Verify: matrix tests for CC0, CC BY, CC BY-NC, SoundCloud, YouTube, community, bundled; editor/apply/share flows respect capability gates.

- [ ] P2 - Source deletion and takedown reconciliation
  - Why: Reddit and other user-generated sources can delete, hide, suspend, or remove content after Aura cached it.
  - Evidence: Reddit developer terms require handling removed/deleted/protected content; Aura stores Reddit permalinks and authors and can cache favorites/downloads.
  - Touches: detail reload paths, favorites/download metadata, source health, report queue from Cycle 1, cache cleanup.
  - Acceptance: source-deleted content stops appearing in remote catalog; favorites/downloads show unavailable/source-deleted state; user can remove local copy; moderator/report queue can hide community mirrors of removed content.
  - Verify: simulate source reload failure/deleted marker; favorite remains navigable but not misrepresented as live remote content; report queue accepts removal reason.
