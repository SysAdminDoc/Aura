# Cycle 121 Research - GitHub Actions Allowlist Guard

## Goal

Make every GitHub Actions `uses:` reference in Aura's workflows reviewable and
machine-checked so unreviewed or floating action refs cannot drift into CI.

## Local Evidence

- Cycle 117 added workflow-specific security snippet checks for Dependency
  Review, OpenSSF Scorecard, and Release.
- The repo also has `verify.yml` and a self-hosted `performance.yml` workflow
  with reusable actions that were not covered by a repository-wide allowlist.
- Source search found 23 `uses:` references across five workflow files.

## Implementation

- Added `docs/distribution/github-actions-allowlist.json` with the required
  workflow files, allowed action refs, and forbidden floating refs.
- Added `tools/github_actions_allowlist_check.py` to scan every workflow YAML
  file for `uses:` entries, reject missing refs, local actions, forbidden
  floating refs, unreviewed actions, unexpected workflow files, missing
  workflow files, and unused allowlist entries.
- Added `test/tools/github_actions_allowlist_check_test.py` coverage for the
  live workflow set and drift cases around unreviewed actions, floating refs,
  unpinned actions, missing workflow files, and unused allowlist entries.
- Wired `.github/workflows/verify.yml` so the allowlist check runs before
  Android setup.
- Updated `docs/distribution/supply-chain.md`, `ROADMAP.md`, `COMPLETED.md`,
  `CHANGELOG.md`, and loop state with the new guard.

## Remaining Risk

- The allowlist pins reviewed action refs by version tag, not immutable commit
  SHA. If Aura later requires full action-SHA pinning, add a separate
  owner-approved migration that updates all workflow references together.
- Production community callable enforcement and live GitHub repository security
  claims still require owner-provided evidence described in the current
  continuation state.
