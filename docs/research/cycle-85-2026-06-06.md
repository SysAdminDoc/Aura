# Cycle 85 - In-App Local Community Cleanup

## Scope

Add the Settings-side local cleanup affordance for the fallback community
identity stored on the current device after backend deletion is complete.

## Sources

- Account deletion local/Auth cleanup sequence:
  `tools/community_account_deletion_cleanup_sequence.py`
- Account deletion policy:
  `docs/community-account-deletion-policy.md`
- Settings community identity surface:
  `app/src/main/java/com/freevibe/ui/screens/settings/SettingsScreen.kt`

## Local Evidence

- Cycle 84 defines the post-completion sequence, but users with Aura still
  installed need a clear local-device action after support confirms backend
  completion.
- The local fallback identity is stored in `aura_community_identity` shared
  preferences. Clearing that local key must refresh the displayed identity
  summary without implying backend RTDB, Firebase Auth, public upload, Storage,
  or moderation deletion.
- `CommunityIdentityProvider` used a lazy fallback value, so clearing the
  preference alone would leave the in-process value stale until restart.

## Implementation

- Reworked `CommunityIdentityProvider` fallback ID access to use a synchronized
  cached accessor and added `clearLocalFallbackIdentity()`.
- Added `CommunityIdentityCleanupState` and
  `SettingsViewModel.clearLocalCommunityIdentity()` to clear the local fallback
  key on the IO dispatcher, refresh the community identity summary, and report
  success/no-op/failure messages.
- Added `Clear local` to the Community identity dialog with a busy state and
  wrapped action row.
- Updated dialog copy to state that local cleanup does not delete backend,
  Firebase Auth, public upload, or moderation records.
- Extended `SettingsViewModelTest` to cover local cleanup delegation, summary
  refresh, and success feedback.
- Updated support, policy, roadmap, changelog, completed ledger, and loop state
  docs.
