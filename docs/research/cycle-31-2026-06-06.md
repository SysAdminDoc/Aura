# Cycle 31 - Release Dependency License Policy Gate

Date: 2026-06-06

## Objective

Add a deterministic release gate that fails PR/main verification and release
builds when Aura's curated dependency or native-payload license IDs are
unknown, disallowed, or missing required release-owner review notes.

## Local Evidence

- `docs/legal/dependency-notices.lock.json` records generated Google OSS
  dependency coordinates and notice-section hashes, but the notice section names
  are library labels rather than normalized SPDX license IDs.
- `docs/legal/dependency-notice-overrides.json` is the current source of
  curated license IDs, source URLs, usage notes, and release-review notes for
  high-risk dependencies and embedded payloads.
- `docs/legal/native-compliance.lock.json` identifies the native payload targets
  that must remain covered by curated overlay entries: FFmpeg, Python, QuickJS,
  and yt-dlp.
- Embedded FFmpeg facts from Cycle 30 expose configure and license-mode strings,
  so policy can fail a future nonfree-mode payload without rerunning manual
  binary inspection.

## Source Review

Primary sources reviewed:

- Cash App Licensee: `https://github.com/cashapp/licensee`
- Licensee 1.x documentation: `https://cashapp.github.io/licensee/docs/1.x/`

Licensee supports Gradle license validation against resolved dependency
variants, including allowed licenses and reasoned exceptions. Aura did not add
Licensee in this cycle because the existing Google OSS notice lock does not
emit normalized license IDs, the existing curated overlay already contains the
release-owner metadata Aura needs, and Licensee would not cover the nested
native payload facts that are now locked by `tools/native_compliance_inventory.py`.

## Implementation

Added `docs/legal/dependency-license-policy.json` with:

- Allowed permissive license IDs.
- Disallowed license patterns.
- Review-required license IDs and patterns.
- Required curated overlay IDs.
- Required coordinate-prefix coverage for current high-risk Gradle dependency
  families.
- Required native payload coverage for FFmpeg, Python, QuickJS, and yt-dlp.

Added `tools/dependency_license_policy.py`:

- Validates the policy file shape.
- Validates curated overlay license IDs against allowed, review-required,
  disallowed, and unknown categories.
- Requires `reviewNote` for every review-required license ID.
- Confirms current dependency/native locks still have required overlay coverage.
- Confirms current native payload targets still have required overlay coverage.
- Scans extracted native payload facts for disallowed policy patterns.

Wired the policy check into:

- `.github/workflows/verify.yml`
- `.github/workflows/release.yml`

Updated:

- `docs/distribution/supply-chain.md`
- `ROADMAP.md`
- `CHANGELOG.md`
- `COMPLETED.md`
- `AUTONOMOUS-LOOP-STATE.md`

## Verification

Executed locally:

```powershell
python -m py_compile tools\dependency_license_policy.py tools\dependency_overlay_check.py tools\dependency_notice_lock.py tools\google_oss_raw_archive.py tools\google_oss_to_markdown.py tools\native_compliance_inventory.py tools\release_artifact_bundle_check.py
python tools\dependency_notice_lock.py --mode check --lockfile docs\legal\dependency-notices.lock.json
python tools\native_compliance_inventory.py --mode check-lock --lockfile docs\legal\native-compliance.lock.json
python tools\dependency_overlay_check.py --overlay docs\legal\dependency-notice-overrides.json
python tools\dependency_license_policy.py --policy docs\legal\dependency-license-policy.json --overlay docs\legal\dependency-notice-overrides.json
```

A temporary overlay copy with `quickjs-runtime` changed to `AGPL-3.0-only`
failed as expected, proving the policy rejects disallowed license IDs.

## Result

Cycle 31 closes the policy gap between drift detection and release permission.
Aura now has checked-in license policy data and a CI/release tool that fails
unknown, disallowed, or unreviewed curated license IDs before a release APK is
published.

## Remaining Risk

Google OSS generated notice files still do not provide normalized license IDs.
New dependencies outside the current required high-risk coordinate prefixes
should continue to be reviewed during dependency updates, and an SBOM/license
normalization lane remains useful after the N-1 toolchain upgrade.

## Next Cycle

Start Cycle 32 by deciding and documenting the public retention policy for
`GOOGLE-OSS-RAW-INPUTS.zip`. The archive is useful for drift review, but the
repo still needs an explicit release-owner decision about whether it should stay
attached to every public tagged release permanently or move to workflow-artifact
retention after the first validation window.
