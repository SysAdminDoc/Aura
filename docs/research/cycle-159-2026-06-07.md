# Cycle 159 research - background work action hints

## Goal

Replace generic background-work deferral copy with user-actionable guidance in
Settings diagnostics and copied support bundles.

## Local evidence

- Cycle 156 added live WorkManager and metered/Data Saver receipts.
- Cycle 157 added persisted worker success, retry, failure, error class, and
  deferral receipts.
- Cycle 158 copied those live receipts into support bundles.
- The remaining local gap was interpretation: users could see a raw deferral
  string but not the next recovery step.

## Implementation decision

`BackgroundWorkStatusRow` now carries an optional `actionHint`. The Android
reader computes it from:

- WorkInfo read errors;
- Data Saver restricted-background status;
- active metered network state for unmetered-only work;
- worker retry/failure receipts for Reddit availability, network/provider I/O,
  Aura Originals download/hash/file-write validation, Android permission cues,
  wallpaper apply failures, and WorkManager retry/failure states.

Settings shows the action hint under each background-work row, and support
bundles serialize it as `action=...` beside the raw deferral receipt.

## Remaining work

- Direct OS scheduler evidence for expedited quota downgrade, low battery,
  Doze/App Standby maintenance windows, and constraint-delay causes still needs
  device/emulator capture.
- Weather no-location skips still return success because the worker has no
  failed operation to retry; a future receipt type could distinguish skipped
  runs from completed refreshes.
