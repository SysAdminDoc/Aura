# Cycle 130 - Provider Credential Storage Policy

## Scope

Cycle 130 finished the provider credential storage classification and Keystore decision follow-up. Owner-gated live callable, hosted deletion URL, production Firebase, and GitHub settings evidence remained unavailable, so this pass continued with a checkable local security policy artifact.

## Local Evidence

- `PreferencesManager.kt` stores Wallhaven, Pexels, Pixabay, Freesound, and Stability values in the `freevibe_prefs` Jetpack DataStore.
- `backup_rules.xml` and `data_extraction_rules.xml` already exclude `datastore/freevibe_prefs.preferences_pb` from backup and device transfer.
- `app/build.gradle.kts` keeps Pexels, Pixabay, Freesound, SoundCloud, and Stability `BuildConfig` defaults blank unless ignored local properties are set.
- `SettingsViewModel` exposed Freesound key state and update methods, but the Settings API-key panel did not include a Freesound clear/edit row.
- `docs/legal/provider-policy.md` still described the pre-Cycle 129 ccMixter HTTP fallback and needed synchronization with the HTTPS-only release posture.

## Decision

Current user-entered provider keys remain in app-private DataStore with backup and device-transfer exclusions. This is not strong at-rest protection and is not described as Keystore-backed encryption. The policy classifies Wallhaven, Pexels, Pixabay, and Freesound as optional quota keys, SoundCloud as a public client ID, and Stability as a paid sensitive secret with explicit user clear control and disclosure.

## Implementation

- Added `docs/security/provider-credential-storage.json` as the machine-readable credential storage policy.
- Added `docs/security/provider-credential-storage.md` as the human-readable storage and no-Keystore decision.
- Added `tools/provider_credential_storage_check.py` and focused tests to check policy/docs coverage, DataStore preference keys, Settings clear controls, BuildConfig blank defaults, backup/device-transfer exclusions, and privacy/diagnostics disclosure.
- Added the missing Freesound API-key row in Settings so every DataStore-backed provider key has a visible edit/clear path.
- Wired the storage policy check into verify and release preflight and required the release workflow snippet in `docs/distribution/github-security-workflows.json`.
- Updated privacy, support diagnostics, supply-chain, provider policy, roadmap, changelog, completion, and loop-state docs.
