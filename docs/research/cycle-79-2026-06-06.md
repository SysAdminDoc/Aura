# Cycle 79 - Account Deletion Apply Simulator

## Scope

Add a non-destructive simulator for reviewed community account deletion plans.
The simulator must exercise the same RTDB null-update shape a future trusted
executor would use while staying fully offline.

## Sources

- Google Play account deletion requirements:
  https://support.google.com/googleplay/android-developer/answer/13327111
- Firebase Realtime Database delete data:
  https://firebase.google.com/docs/database/android/read-and-write#delete_data
- Cycle 78 review gate:
  `tools/community_account_deletion_review.py`
- Cycle 74 dry-run planner:
  `tools/community_account_deletion_plan.py`

## Local Evidence

- The Cycle 78 review receipt hashes the plan and lookup evidence, but it does
  not prove the null updates remove paths from an export.
- A future trusted executor needs one more local gate that rejects stale review
  receipts and detects update paths that remain after applying the plan.
- Retained aggregate votes, moderation records, public upload metadata, owner
  upload indexes, and Storage objects must stay outside account marker deletes.

## Implementation

- Added `tools/community_account_deletion_apply_simulator.py`.
- The simulator validates the review receipt against the plan hash, UID-key
  hash, retained roots, update count, and `readyForTrustedApply` status.
- It applies null updates to a deep copy of the RTDB export, prunes empty
  objects, and emits a hashed receipt with deleted, missing-before, and
  remaining-path counts.
- It can optionally write a simulated post-delete snapshot for private
  operator review.
- Tightened `tools/community_account_deletion_review.py` so plans cannot delete
  retained aggregate vote counts, moderation roots, public upload metadata, or
  owner-upload indexes.
- Added `test/tools/community_account_deletion_apply_simulator_test.py`.
- Wired the simulator into Firebase backend CI change detection.
- Updated support, policy, runbook, roadmap, changelog, completed ledger, and
  loop state docs.
