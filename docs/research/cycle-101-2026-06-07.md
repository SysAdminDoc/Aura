# Cycle 101 - Profile Callable Emulator Coverage

## Goal

Add the first emulator-backed callable handler coverage now that all seven
contracted community callable exports have handler cores.

## Research

- `firebase.json` already defines a Database emulator on port 9000 and a
  Functions emulator on port 5001.
- Existing Firebase tests under `test/firebase/` use `firebase emulators:exec`
  and the root npm scripts for RTDB and Storage rules coverage.
- The current handler unit tests use fake backends, so they prove handler
  decisions but do not prove the real Admin SDK backend writes the expected
  RTDB rows.
- The full callable wire protocol still needs Auth and App Check emulator
  wiring. This cycle adds a smaller but concrete RTDB-emulator-backed handler
  persistence slice for `updateCreatorProfile`.

## Implementation

- Added `test/firebase/functions.profile.test.mjs`.
- Added `npm run test:functions-emulator`, which builds `functions/` and runs
  the profile handler test under `firebase emulators:exec --only database`.
- Added the same script to the `firebase-rules` CI lane after the Functions
  unit tests and before the rules suite.
- The test resolves `firebase-admin` from the `functions/` package so the root
  harness does not need a duplicate Admin SDK dependency.
- The profile handler now defaults to its Firebase Admin SDK backend when no
  fake backend is passed, allowing the emulator test to invoke the handler core
  with the real backend.
- The emulator test covers:
  - accepted profile update writes to `/creator_profiles/{uid}`;
  - quota rows under `/community_write_quotas/{uid}/{yyyyMMdd}/profile_edits`;
  - dedupe markers under `/community_write_dedupe/{uid}/profile_edits`; and
  - unchanged-profile idempotency before quota mutation.
- Updated `tools/community_backend_manifest.py` so Functions-related test
  scripts are captured in `docs/community-backend-manifest.json`.
- Refreshed `docs/community-backend-manifest.json`.
- Updated backend runbook, roadmap, changelog, completed log, and loop state.

## Remaining Risk

This is RTDB-emulator-backed handler persistence coverage, not a Firebase
callable wire-protocol test. The remaining callable surfaces still need the
same database-backed integration slice, and all surfaces still need full
callable protocol coverage, Android migration, owner-approved deploy evidence,
Firebase Console App Check evidence, and direct RTDB rule tightening.
