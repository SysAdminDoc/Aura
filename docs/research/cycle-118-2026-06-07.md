# Cycle 118 Research - Dependabot Update Policy Guard

## Goal

Add checked Dependabot version-update coverage for Aura's active dependency
surfaces while live repository security settings remain owner-gated.

## Local Evidence

- Cycle 117 added a repository-local policy guard for Dependency Review,
  OpenSSF Scorecard, and Release workflows, but live GitHub security settings
  still require owner/admin access.
- The repository has GitHub Actions workflows, Gradle build files,
  root Firebase rules npm dependencies, and Firebase Functions npm dependencies
  under `functions/`.
- No `.github/dependabot.yml` existed at the start of this cycle, so version
  update PR cadence was not tracked in source.

## Implementation

- Added `.github/dependabot.yml` with weekly version-update PR coverage for
  GitHub Actions, Gradle, root npm, and Functions npm.
- Each update entry targets `main`, uses `America/New_York` Monday scheduling,
  caps open PRs at five, uses the `deps` commit prefix, and applies
  `dependencies` plus `security` labels.
- Added `tools/dependabot_config_check.py` with a dependency-free constrained
  YAML reader and validator for the four expected update surfaces, schedule,
  target branch, PR limit, commit prefix, and labels.
- Added `test/tools/dependabot_config_check_test.py` coverage for the live
  config and drift cases around unsupported surfaces, duplicate surfaces,
  cadence drift, missing labels, and excessive open PR limits.
- Wired `.github/workflows/verify.yml` so the Dependabot update policy check
  runs in the always-on verify job.
- Updated `docs/distribution/supply-chain.md`, `ROADMAP.md`, `COMPLETED.md`,
  `CHANGELOG.md`, and loop state with the new guard.

## Remaining Risk

- Dependabot version-update PR configuration is now tracked in source, but
  live Dependabot alerts, Dependabot security updates, code scanning, secret
  scanning, and branch protection still require owner/admin verification in
  GitHub.
- Production community callable enforcement still requires owner-approved
  deploy evidence, Firebase Console App Check evidence, valid private live
  invocation evidence, and direct RTDB rule tightening.
