# Cycle 76 - Community Deletion Request Routing

## Scope

Add a private request route for community account deletion requests without
publishing full Firebase UIDs or inventing a support email address that does
not exist in the repo.

## Sources

- Google Play account deletion requirements:
  https://support.google.com/googleplay/android-developer/answer/13327111
- Firebase Auth delete users:
  https://firebase.google.com/docs/auth/android/manage-users#delete_a_user
- Cycle 75 request surface:
  `docs/research/cycle-75-2026-06-06.md`
- Cycle 74 deletion policy:
  `docs/community-account-deletion-policy.md`

## Local Evidence

- `README.md` routes crash/ANR support through Settings diagnostics and
  tracked support docs.
- No checked-in support email address or hosted deletion URL exists yet.
- `Settings > Community identity` can show a deletion request code only when a
  Firebase community identity already exists.
- The Cycle 74 planner remains dry-run only, so user-facing copy must not imply
  deletion is self-service today.

## Implementation

- Added `CommunityDeletionRequest.kt` with a redacted request subject/body
  builder.
- The request body includes the `AURA-` request code, identity suffix, auth
  label, and deletion statement, but not the full Firebase UID.
- Added a `Share` action to the Settings community identity dialog when a
  deletion request code exists.
- Added `docs/support/community-account-deletion.md` with user and operator
  handling instructions.
- Linked the support doc from `README.md`.
- Updated policy, roadmap, changelog, completed ledger, and loop state.
