# Cycle 144 - SDK Data Safety Surface Gate

## Scope

Cycle 144 continued the checked Data safety matrix after the manifest
permission, network endpoint, and local storage slices. Owner-gated live
callable evidence, hosted deletion URL publication, production Firebase dry
runs, GitHub security settings evidence, signed release dry-run evidence, and
fresh store screenshots remained unavailable locally, so this pass addressed
the next checkable privacy gap: SDK-backed data surfaces.

## Current Finding

Aura's privacy matrix already listed the `firebase-community` network row and
local community identity/cache rows, but it did not separately gate SDK
surfaces that can collect, process, or share data through third-party provider
libraries. The current dependency graph includes Firebase Auth, Realtime
Database, Storage, Functions, App Check, Play Integrity, Play services ML Kit
subject segmentation, and Play services module install support.

Google Play Data safety guidance requires developers to account for SDK and
library sharing/collection, not just direct app endpoints. Aura therefore needs
a machine-checked SDK ledger tied to both Gradle dependency markers and source
files.

## Local Evidence

- `app/build.gradle.kts` declares Firebase Auth, Realtime Database, Storage,
  Functions, App Check Play Integrity/debug, Play services ML Kit subject
  segmentation, and Play services base/module-install dependencies.
- `CommunityIdentityProvider.kt` and `VoteRepository.kt` use Firebase Auth
  identity for community features.
- `VoteRepository.kt`, `CommunityReportRepository.kt`,
  `CommunityBlockRepository.kt`, `CreatorProfileRepository.kt`, and
  `CollectionExporter.kt` use Firebase Realtime Database for community rows.
- `UploadRepository.kt`, `WallpaperUploadRepository.kt`,
  `CommunityReportRepository.kt`, and `CommunityUploadDeletionHelpers.kt` use
  Firebase Storage for community media and report evidence.
- `CommunityCallableClient.kt` and `CommunityQuotaPolicy.kt` use Cloud
  Functions callables for report, vote, follow, block, upload finalizer, and
  profile write paths.
- `FreeVibeApp.kt` installs App Check before Firebase-backed community startup
  work; debug/release `AppCheckInstaller.kt` select debug or Play Integrity
  providers.
- `SmartCropDetector.kt` and `ParallaxWallpaperService.kt` use Play services
  ML Kit subject segmentation, and `ParallaxWallpaperService.kt` requests the
  unbundled model module through Play services.

## Implementation

- Added `dependencyFiles` and `sdkSurfaces` to
  `docs/privacy/data-safety.json`.
- Added six SDK rows: Firebase Auth, Firebase Realtime Database, Firebase
  Storage, Firebase Functions, Firebase App Check, and Play services ML Kit
  subject segmentation/module install.
- Extended `tools/privacy_data_safety_check.py` to require non-empty SDK rows,
  unique surface IDs, existing source paths, supported collection/sharing
  statuses, matching Markdown rows, and dependency markers found in the tracked
  Gradle files.
- Added `sharedWithServiceProviders` as a supported sharing status for Firebase
  and Google service-provider SDK rows.
- Extended `docs/privacy/data-safety.md` with an SDK Surface Ledger and release
  checklist language.
- Updated release dry-run and supply-chain docs so release checks explicitly
  include SDK surface drift.
- Added focused unit tests for missing SDK dependency markers, missing SDK
  source files, and missing SDK Markdown rows.
