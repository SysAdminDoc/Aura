# Cycle 78 - Account Deletion Review Gate

## Scope

Add a local operator review gate between request-code lookup and any future
trusted account deletion executor. The gate must improve deletion evidence
without applying RTDB, Storage, or Auth changes.

## Sources

- Google Play account deletion requirements:
  https://support.google.com/googleplay/android-developer/answer/13327111
- Firebase Realtime Database delete data:
  https://firebase.google.com/docs/database/android/read-and-write#delete_data
- Cycle 77 request-code lookup:
  `tools/community_deletion_request_lookup.py`
- Cycle 74 dry-run planner:
  `tools/community_account_deletion_plan.py`

## Local Evidence

- The request-code lookup now emits matched UID evidence, but the dry-run
  planner still accepts a manually provided UID.
- The plan output is a multi-path update shape, so any future executor needs a
  guard that blocks non-null updates before destructive work can run.
- The account deletion policy requires retained aggregate votes, moderation
  records, and public upload workflow boundaries to stay visible in evidence.

## Implementation

- Added `tools/community_account_deletion_review.py`.
- The review tool validates exactly one request-code lookup match, matching
  sanitized UID keys, null-only plan updates, update category coverage, and
  required retained roots.
- The tool emits a redacted receipt with update/category counts, evidence
  counts, a UID-key hash/suffix, a lookup evidence hash, and a plan hash.
- Added `test/tools/community_account_deletion_review_test.py`.
- Wired the tool into Firebase backend CI change detection.
- Updated the support doc, account deletion policy, backend runbook, roadmap,
  changelog, completed ledger, and loop state.
