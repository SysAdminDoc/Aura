# Cycle 104 - Follow Callable Emulator Coverage

## Goal

Extend the RTDB-emulator-backed callable handler persistence lane from profile,
report, and vote writes to creator follow state changes.

## Research

- `setCreatorFollow` writes or removes one private follow row under
  `/creator_follows/{uid}/{creatorKey}` plus quota and dedupe ledgers.
- Follow and unfollow use separate dedupe keys because they are opposite state
  transitions for the same creator.
- The focused Functions test already verifies payload normalization, no-op
  idempotency, same-state dedupe, cooldown, daily-limit, Auth, and App Check
  behavior using a fake backend.

## Implementation

- Added `test/firebase/functions.follow.test.mjs`.
- Updated `setCreatorFollowHandler()` to default to its real Firebase Admin SDK
  backend when no fake backend is passed.
- The follow emulator test verifies:
  - accepted follow writes under `/creator_follows/{uid}/{creatorKey}`;
  - server-derived follower UID and followed timestamp;
  - quota rows under `/community_write_quotas/{uid}/{yyyyMMdd}/follows`;
  - follow dedupe markers under
    `/community_write_dedupe/{uid}/follows/{creatorKey}_follow`;
  - accepted unfollow removes the follow row; and
  - missing-unfollow idempotency before quota mutation.
- Refreshed `docs/community-backend-manifest.json`.
- Updated roadmap, changelog, completed log, backend runbook, and loop state.

## Remaining Risk

This is RTDB-emulator-backed handler persistence coverage, not a Firebase
callable wire-protocol test. Blocks, sound uploads, and wallpaper uploads still
need the same persistence lane, and all surfaces still need full callable
protocol coverage, Android migration, owner-approved deploy evidence, Firebase
Console App Check evidence, and direct RTDB rule tightening.

## Next

- Add RTDB-emulator-backed handler persistence coverage for user blocks, sound
  uploads, and wallpaper uploads.
- Add full callable wire-protocol coverage when Auth/App Check emulator wiring
  is available.
- Add Android callable adapters for reports, votes, follows, user blocks,
  upload metadata finalization, and profile edits.
