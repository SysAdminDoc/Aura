# Cycle 66 - Legacy Upload Backfill Plan

## Scope

Cycle 66 adds a dry-run backfill plan for legacy community upload rows that lack
canonical `storagePath` and private owner-index metadata.

## Primary Sources

- Firebase Realtime Database Android read/write/delete:
  https://firebase.google.com/docs/database/android/read-and-write
- Firebase DatabaseReference API:
  https://firebase.google.com/docs/reference/android/com/google/firebase/database/DatabaseReference
- Firebase Storage Android delete files:
  https://firebase.google.com/docs/storage/android/delete-files

## Local Evidence

- New upload rows write `storagePath`, `uploaderUid`, and
  `/owner_uploads/{uid}/sounds|wallpapers/{uploadId}`.
- Legacy rows may only have `downloadUrl` plus `uploaderId`.
- Owner/admin delete actions intentionally fail closed when `storagePath` is
  blank because public download URLs are not a stable delete handle.
- Firebase Storage download URLs can encode object paths in
  `firebasestorage.googleapis.com/.../o/<encodedPath>` or in
  `storage.googleapis.com/<bucket>/<objectPath>` URLs.

## Implementation

- Added `tools/community_upload_backfill_plan.py` to parse RTDB exports, derive
  safe Storage paths from legacy URLs, and emit dry-run multi-path RTDB updates
  for `storagePath`, missing `uploaderUid`, and `/owner_uploads` index rows.
- Added `test/tools/community_upload_backfill_plan_test.py` covering Firebase
  Storage URL parsing, Google Storage URL parsing, owner-index update payloads,
  already-backfilled rows, and blocked unsafe rows.
- Updated the Firebase backend CI path filter so all `test/tools` checks run
  when backend lifecycle/backfill tools change.
- Added `docs/community-upload-backfill.md` with candidate requirements, apply
  gate, evidence requirements, and remaining trusted-writer work.
- Linked the backfill runbook from upload deletion and Storage lifecycle docs.
