# Project Research and Feature Plan

**Project:** Aura (`com.freevibe`)
**Cycle:** 21
**Date:** 2026-06-06
**Repo state:** `main`, uncommitted Cycle 18/19/20 roadmap updates present, `versionCode 112`

## Executive Summary

Cycle 21 resolved the Cycle 20 decision point: do not implement Google's stock OSS notices runtime path in the real repo yet. Keep the Google Gradle plugin as the first implementation lane, but use it to generate release notice artifacts and a human-readable `THIRD-PARTY-NOTICES.md` first.

The reason is release-runtime risk. In the isolated Google spike clone, adding `com.google.android.gms:play-services-oss-licenses:17.5.1` generated notices successfully, but it also pulled a large UI dependency wave into `releaseRuntimeClasspath`, including Activity Compose 1.12.1, Compose 1.11.0-beta02 artifacts, AppCompat 1.7.1, Material Components 1.13.0, and credential-related dependencies. Removing the runtime dependency while keeping the Google OSS licenses Gradle plugin still allowed `:app:releaseOssLicensesTask` to pass and generate useful notice outputs from Aura's existing release runtime graph.

The safest next implementation shape is therefore:

1. Apply the Google OSS licenses Gradle plugin in the real repo with reviewed dependency verification metadata.
2. Do not add `play-services-oss-licenses` runtime or the stock `OssLicensesMenuActivity` until dependency convergence is audited.
3. Add a repo-owned conversion script that turns the generated Google raw resources and `dependencies.json` into `THIRD-PARTY-NOTICES.md`.
4. Keep `ProviderDisclosure.kt` as the source of truth for content-source/provider policy rows in the custom Compose Licenses screen.
5. Treat AboutLibraries 14.2.1 as secondary unless a later config pass proves full release-runtime coverage without Windows compliance export path errors.

## Runtime Dependency Risk

The clone also ran a release runtime dependency graph check with `play-services-oss-licenses:17.5.1` still present. That dependency was not just a small notice UI runtime; it caused broad dependency upgrades and additions in Aura's release classpath.

Observed risky convergence when the runtime dependency was present:

- `androidx.activity:activity-compose:1.9.3 -> 1.12.1`
- Compose artifacts from `1.7.6` to `1.11.0-beta02`
- `com.google.android.material:material:1.13.0`
- AppCompat 1.7.1 and related AppCompat resources
- credentials and other additional AndroidX/Google transitive dependencies

After removing `play-services-oss-licenses`, the release runtime graph check no longer showed `play-services-oss-licenses`, Activity Compose 1.12.1, Compose 1.11.0-beta02, or Material Components 1.13.0. It returned to Aura's existing Compose/Activity stack, including:

- `androidx.activity:activity-compose:1.9.3`
- Compose `1.7.6`
- Material3 `1.3.1`

Implementation implication: the real repo should not add the Google runtime dependency or wire the stock Google notice activity until dependency convergence is intentionally audited and accepted. The plugin-only generation path gives Aura the generated release notice artifacts without introducing that UI-runtime drift.

## ProviderDisclosure Preservation

`ProviderDisclosure.kt` and `ProviderDisclosureTest.kt` already provide code-backed content-source coverage:

- every `ContentSource` has exactly one disclosure row
- user-visible policy fields are asserted non-empty
- `LicensesScreen.kt` maps `providerDisclosures` into the "Content Sources" section

Cycle 21 keeps that model intact. Generated dependency notices should replace or supplement the hand-maintained "Libraries" section, but they should not replace the content-source section because Maven dependency notices cannot describe provider status, terms URLs, cache policy, user actions, store disclosure, community uploads, bundled media provenance, or AI-generated content.

## Decision

Do not implement the full Google stock activity path in the real repo yet.

Implement a narrower first slice instead:

- Google OSS licenses Gradle plugin only.
- reviewed `gradle/verification-metadata.xml` update for the plugin artifacts.
- release task that runs `:app:releaseOssLicensesTask`.
- repo-owned `tools/google_oss_to_markdown.*` conversion script.
- generated `THIRD-PARTY-NOTICES.md` as a release artifact and checksum input.
- custom Compose Licenses screen remains the user-facing surface, with `ProviderDisclosure` preserving content-source policy coverage.

## Recommended Roadmap Insertions

1. Add a P0 item for plugin-only Google OSS notice generation.
2. Mark `play-services-oss-licenses` runtime/stock activity as blocked behind dependency convergence audit.
3. Promote `THIRD-PARTY-NOTICES.md` conversion from optional spike to first implementation slice.
4. Preserve the Cycle 20 verification metadata gate, but scope it to the plugin-first implementation rather than the runtime dependency.
5. Keep AboutLibraries 14.2.1 secondary and AboutLibraries 15.x deferred until the AGP upgrade.
