# Cycle 52 - Admin Report Review

## Scope

Cycle 52 turns the private report intake from Cycle 51 into an admin workflow.
It adds a custom-claim-gated review surface for open reports and connects
report actions to the existing moderation hide list.

## Local Evidence

- `CommunityReportRepository.submitReport()` created private report records, but
  no screen subscribed to `/community_reports`.
- `VoteRepository.moderateHide()` and `moderateUnhide()` already owned the
  public hide list under `/moderation/{contentId}`.
- `SettingsScreen` already hosted community management entry points such as the
  creator profile, making it the least disruptive admin entry point.
- `database.rules.json` allowed admin reads but did not yet declare an index for
  the report status query used by an open-report queue.

## Implementation

- Added `CommunityReportRecord` plus storage-to-enum helpers for report queue
  rows.
- Added `CommunityReportRepository.reports()` as a Flow-backed open-report
  reader with status filtering and newest-first ordering.
- Added `CommunityReportsScreen` and `CommunityReportsViewModel` with admin
  gating, open report cards, refresh feedback, and Hide, Dismiss, and Restore
  actions.
- Wired Hide and Restore to `VoteRepository.moderateHide()` and
  `VoteRepository.moderateUnhide()` before writing report resolution metadata.
- Added Settings navigation for custom-claim admins and registered the
  `community_reports` route.
- Added `.indexOn: ["status"]` for `/community_reports` so the open-report
  query is explicit in RTDB rules.
- Updated the support note, roadmap, completion ledger, changelog, and loop
  state.

Focused tests prove:

- Hide writes the global moderation entry before closing the report as hidden.
- Dismiss closes the report without touching moderation.
- Restore removes the global moderation entry before closing the report as
  restored.
- Non-admin ViewModels do not subscribe to the private report feed.
- Settings exposes admin community moderation access from `VoteRepository`.
