# Cycle 108 - Android Report Callable Migration

## Goal

Start the Android callable migration with the lowest-risk write surface:
community report submission. Reports do not have an upload-progress flow, and
the backend already has focused unit coverage plus RTDB-emulator-backed handler
persistence coverage.

## Research

- Firebase's callable client SDK is the supported Android path for `onCall`
  functions. The SDK includes Firebase Auth and App Check tokens when available,
  and the Android dependency is meant to be added under the Firebase BoM.
- Firebase App Check callable enforcement supports limited-use token
  consumption. Android clients request that mode with
  `HttpsCallableOptions.Builder.setLimitedUseAppCheckTokens(true)`.
- Aura's current Firebase BoM remains `34.13.0` to avoid unrelated dependency
  churn in this cycle; adding `firebase-functions` under that BoM resolved the
  Android Functions client to `22.1.1`.
- The existing `submitCommunityReport` backend rejects client-provided
  `reporterUid`, derives timestamps server-side, and expects the standard
  envelope: `operationId`, `clientSentAt`, and `payload`.

## Implementation

- Added `firebase-functions` to the Android release runtime under the existing
  Firebase BoM.
- Added `CommunityCallableClient`, `CommunityCallableInvoker`, and the
  Firebase-backed invoker using `FirebaseFunctions.getHttpsCallable`.
- Added limited-use App Check token selection from the existing
  `CommunityQuotaPolicies.reports` callable contract.
- Added a shared callable envelope builder and report write response parser.
- Added `buildCommunityReportCallablePayload()` so Android report requests omit
  server-owned `reporterUid`, `reportedAt`, `status`, and `contentKey`.
- Updated `CommunityReportRepository.submitReport()` to try
  `submitCommunityReport` first when Firebase Auth has a current UID, while
  preserving the direct RTDB write as a compatibility fallback when the callable
  endpoint is not deployed yet or Firebase Auth is unavailable.
- Added focused unit coverage for the callable request envelope, limited-use
  token flag, response parsing, and server-owned-field omission.
- Refreshed Gradle dependency verification metadata and the generated
  dependency notice lock. Existing Firebase and Google Play services overlay
  entries cover the new runtime coordinates.

## Remaining Risk

This is Android migration code, not a production enforcement claim. The direct
RTDB report fallback remains until owner-approved Functions deploy evidence,
callable protocol coverage, App Check console evidence, and direct report-rule
tightening are complete.
