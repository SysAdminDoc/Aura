# Cycle 107 - Wallpaper Upload Callable Emulator Coverage

## Goal

Complete the RTDB-emulator-backed callable handler persistence lane by adding
community wallpaper upload finalization coverage.

## Research

- `finalizeCommunityWallpaperUpload` writes public metadata under
  `/community_wallpapers/{uploadId}` and owner index rows under
  `/owner_uploads/{uid}/wallpapers/{uploadId}`.
- Wallpaper upload dedupe is derived from the normalized Storage path, so the
  same committed blob path should be idempotent before another quota mutation.
- The focused Functions test already verifies metadata normalization,
  dimension/file-size/file-type bounds, storage-path ownership,
  storage-path dedupe, cooldown, daily-limit, Auth, and App Check behavior
  using a fake backend.

## Implementation

- Added `test/firebase/functions.wallpaper-upload.test.mjs`.
- Updated `finalizeCommunityWallpaperUploadHandler()` to default to its real
  Firebase Admin SDK backend when no fake backend is passed.
- The wallpaper upload emulator test verifies:
  - accepted public metadata writes under `/community_wallpapers/{uploadId}`;
  - owner index writes under `/owner_uploads/{uid}/wallpapers/{uploadId}`;
  - server-derived uploader UID, upload ID, timestamps, rights timestamp, and
    zero-vote initialization;
  - quota rows under `/community_write_quotas/{uid}/{yyyyMMdd}/wallpaper_uploads`;
  - storage-path dedupe markers under
    `/community_write_dedupe/{uid}/wallpaper_uploads/{dedupeKey}`; and
  - same-storage-path idempotency before additional quota mutation.
- Refreshed `docs/community-backend-manifest.json`.
- Updated roadmap, changelog, completed log, backend runbook, callable quota
  enforcement doc, and loop state.

## Remaining Risk

All seven callable handler surfaces now have focused Functions tests and
RTDB-emulator-backed handler persistence coverage. This is still not full
Firebase callable wire-protocol coverage, and the Android app still needs
callable repository adapters plus owner-approved deploy evidence, Firebase
Console App Check evidence, and direct RTDB rule tightening.
