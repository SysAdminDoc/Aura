# Cycle 100 - Creator Profile Callable Handler

## Goal

Complete the remaining contracted callable handler by moving creator profile
updates from a broad owner-writable RTDB path toward a server-owned Cloud
Functions handler core.

## Research

- `docs/community-callable-contract.json` already reserves
  `updateCreatorProfile`, the `CreatorProfileUpdateInput` payload schema, Auth
  and App Check requirements, a 12/day quota, a 5-minute cooldown, and the
  final write path `/creator_profiles/{uid}`.
- `database.rules.json` allows public reads and owner/admin writes under
  `/creator_profiles/{uid}` but does not constrain field names or timestamps.
- `CreatorProfileRepository` currently reads derived creator dashboard state
  from uploads, follows, favorites, and block lists. It has follow/unfollow
  write methods but no profile edit UI or repository method yet, so the backend
  handler must stay narrow and avoid depending on client-owned profile fields.
- The previous profile edit dedupe key was only `profileUid`. With the shared
  7-day dedupe marker TTL, that would make distinct profile edits look like
  duplicates for too long. The contract now uses profile UID plus normalized
  public profile hash.

## Implementation

- Added `functions/src/profileHandler.ts`.
- Switched `updateCreatorProfile` from the fail-closed scaffold to
  `createUpdateCreatorProfileCallable()`.
- The handler now:
  - requires Firebase Auth and App Check through the shared identity guard;
  - validates the common envelope (`operationId`, `clientSentAt`, `payload`);
  - rejects client-supplied profile UID, owner UID, `createdAt`, and
    `updatedAt` fields;
  - normalizes public `displayName`, `bio`, `websiteUrl`, and `avatarUrl`
    fields;
  - requires optional URLs to use HTTPS;
  - derives `profileUid`, `createdAt`, and `updatedAt` server-side;
  - treats an unchanged public profile row as an idempotent duplicate before
    quota reservation;
  - derives a hashed dedupe key from the authenticated profile UID plus the
    normalized public profile payload;
  - reserves UTC quota through the shared quota engine; and
  - writes `/creator_profiles/{uid}` and the server-owned dedupe marker in one
    backend commit.
- Added `functions/test/updateCreatorProfile.test.cjs` for accepted update,
  unchanged-profile duplicate, active normalized-profile dedupe, cooldown,
  daily-limit, unauthenticated, missing-App-Check, UID/timestamp override, and
  invalid public-copy paths.
- Updated `CommunityQuotaPolicies`, `functions/src/communityContract.ts`,
  `docs/community-callable-contract.json`, and
  `tools/community_callable_contract_check.py` for the refined profile dedupe
  key.
- Refreshed `docs/community-backend-manifest.json`.
- Updated callable, quota, backend runbook, roadmap, changelog, completed log,
  and loop state docs.

## Remaining Risk

The profile edit handler has focused Functions unit coverage, not a live
Emulator Suite callable invocation through the Firebase protocol. Android does
not yet expose a profile-edit repository adapter or UI, and production reliance
still needs emulator coverage, Android callable migration, owner-approved deploy
evidence, Firebase Console App Check evidence, and direct RTDB rule tightening.
