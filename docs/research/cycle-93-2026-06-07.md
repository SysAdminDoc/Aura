# Cycle 93 - Cloud Functions Scaffold

## Goal

Start the deployable Cloud Functions lane for the Cycle 63/91 community
callable quota contract without enabling partial production writes.

## Research

- Firebase's callable docs use `onCall` and include Auth/App Check context on
  callable requests.
- Firebase App Check for Cloud Functions supports `enforceAppCheck` and
  `consumeAppCheckToken`; replay protection is intended for sensitive endpoints
  and adds latency.
- Firebase's TypeScript Functions guide supports a `functions/` project with a
  build script and Firebase predeploy hook.
- Current npm package metadata shows `firebase-functions` 7.2.5 and
  `firebase-admin` 13.10.0 support Node 18 or newer, so Node 20 is a stable
  runtime target for this repo's CI lane.

## Implementation

- Added `functions/package.json`, `functions/tsconfig.json`, and
  `functions/package-lock.json` for a Node 20 TypeScript Functions project.
- Added `functions/src/communityContract.ts` as the runtime mirror of
  `docs/community-callable-contract.json`.
- Added `functions/src/quotaEngine.ts` with pure UTC quota-day, duplicate,
  cooldown, daily-limit, accepted-state, blocked-state, and dedupe-marker
  decisions.
- Added `functions/src/callableScaffold.ts` and `functions/src/index.ts` so all
  seven contracted callables export with Auth/App Check requirements and
  fail-closed `failed-precondition` responses until write handlers land.
- Added `functions/test/communityContract.test.cjs` and
  `functions/test/quotaEngine.test.cjs` for manifest sync, runtime options,
  limited-use token choices, UTC day boundaries, duplicate handling, cooldown,
  and daily-limit behavior.
- Updated `firebase.json`, `.github/workflows/verify.yml`, `package.json`,
  `.gitignore`, `tools/community_backend_manifest.py`, and
  `docs/community-backend-manifest.json` so Functions source is part of backend
  verification.
- Updated the callable quota docs, backend runbook, roadmap, changelog,
  completed log, and loop state.

## Verification

- `npm --prefix functions test`
- `py -3 tools\community_backend_manifest.py --mode check`
- `py -3 tools\community_callable_contract_check.py --contract docs\community-callable-contract.json`

`npm --prefix functions audit --audit-level=high` passed. The current Firebase
Admin/Functions dependency chain still reports moderate transitive `uuid`
advisories; `npm audit fix --force` would downgrade Firebase Admin across a
breaking boundary, so this pass keeps the current packages and records the
residual risk.
