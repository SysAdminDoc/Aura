# Cycle 115 Research - Callable Wire Protocol Guard

## Goal

Make the Android callable wire protocol machine-checkable for all contracted
community write surfaces without claiming live callable production enforcement.

## Local Evidence

- `docs/community-callable-contract.json` is the backend callable quota
  contract for reports, votes, follows, user blocks, sound upload finalizers,
  wallpaper upload finalizers, and profile edits.
- `CommunityCallableClient.kt` now has Android callable methods for all seven
  contracted surfaces and uses a shared `CommunityCallableRequest` envelope.
- `CommunityCallableClientTest.kt` has focused request-envelope coverage for
  function names, payload normalization, operation-ID prefixes, response
  resource IDs, and App Check token selection.
- Live callable invocation evidence is still blocked by owner-approved deploy
  and App Check environment evidence, so this cycle adds a static plus unit
  guard for client/contract drift.

## Implementation

- Added `docs/community-callable-wire-protocol.json` as the Android-facing
  callable wire-protocol manifest. It maps each contracted surface to its
  callable function name, quota-policy accessor, Android method, backend
  payload schema, Android input type, payload builder, operation-ID prefix,
  resource-ID response field, App Check token choice, and focused client test.
- Added `tools/community_callable_wire_protocol_check.py` to compare the wire
  manifest against the backend callable contract and Android client source.
  The guard verifies method signatures, quota policy reads, shared envelope
  use, payload builders, limited-use token routing, operation-ID prefixes,
  response resource-ID mapping, and focused test assertions.
- Added `test/tools/community_callable_wire_protocol_check_test.py` to cover
  the live manifest and negative drift cases for missing surfaces, token
  choice drift, missing Android methods, Android input type drift, and missing
  focused tests.
- Wired `.github/workflows/verify.yml` so backend-affecting changes run the new
  wire-protocol check before the broader backend tool test sweep.
- Updated the callable quota enforcement and backend deploy runbooks with the
  new manifest, preflight command, and release checklist expectations.

## Remaining Risk

- This guard proves Android source/test coverage matches the callable contract;
  it does not prove live HTTPS callable invocation against a deployed Firebase
  project.
- Production enforcement still needs owner-approved deploy evidence, App Check
  console evidence, live callable invocation evidence, and direct RTDB rule
  tightening.
- Compatibility direct-write fallbacks must stay until deployed callable
  endpoints and rollout evidence exist for the app's Firebase project.
