# Cycle 67 - Community Deletion Tombstones

## Scope

Cycle 67 defines retention behavior for deleted community sound and wallpaper
uploads, then implements private deletion tombstones for owner deletes and admin
rights takedowns.

## Primary Sources

- Firebase Realtime Database Android read/write/delete:
  https://firebase.google.com/docs/database/android/read-and-write
- Firebase DatabaseReference API:
  https://firebase.google.com/docs/reference/android/com/google/firebase/database/DatabaseReference
- Firebase Storage Android delete files:
  https://firebase.google.com/docs/storage/android/delete-files
- Firebase Realtime Database Security Rules:
  https://firebase.google.com/docs/database/security

## Local Evidence

- Owner delete flows already remove the Storage object before the RTDB
  multi-location metadata update.
- Admin rights takedown delete flows already write private receipts and remove
  public metadata plus owner indexes.
- Without a private tombstone, successful deletes remove public metadata and
  leave no minimal upload-level evidence for troubleshooting a removed object.
- Vote aggregates and voter markers still use the existing public vote tree, so
  upload deletion cannot truthfully claim vote-marker minimization yet.

## Implementation

- Added `CommunityUploadDeleteReason` and
  `/community_upload_deletions/{publicId}` tombstone paths to
  `CommunityUploadOwnership.kt`.
- Extended `buildCommunityUploadDeleteUpdates()` so owner and admin delete
  flows remove public metadata plus owner indexes while writing a private
  tombstone with upload ID, content type, metadata path, Storage path, uploader,
  deleter, timestamp, and reason.
- Tightened tombstone payload validation so the recorded Storage path must live
  under the uploader-scoped `sounds/{uid}/` or `wallpapers/{uid}/` prefix.
- Updated sound, wallpaper, and admin rights delete repositories to write
  `OWNER_DELETE` or `ADMIN_TAKEDOWN` tombstones.
- Added RTDB rules and emulator coverage for private admin-only tombstone reads,
  owner-only initial owner-delete writes, admin takedown writes, owner update
  denial, wrong Storage root denial, wrong owner prefix denial, and owner misuse
  of the admin takedown reason.
- Added `docs/community-deletion-retention-policy.md` and linked it from the
  upload deletion runbook.
