# Cycle 111 Research - Android User-Block Callable Migration

## Goal

Move Android community block and unblock writes from direct Realtime Database
first-write behavior to the existing `setCommunityUserBlock` callable when
Firebase Auth is available, while keeping compatibility fallback until deploy
evidence and direct-rule tightening are complete.

## Local Evidence

- `functions/src/blockHandler.ts` accepts an envelope with `operationId`,
  `clientSentAt`, and a payload containing `blockedUid`, `blocked`, and an
  optional `reason`.
- The backend derives blocker UID from Firebase Auth, requires App Check,
  normalizes blocked UID, rejects self-blocks, treats already matching block
  state as a duplicate success, reserves quota, writes or removes
  `/community_user_blocks/{uid}/{blockedUid}` and
  `/community_blocked_by/{blockedUid}/{uid}`, and records a dedupe marker.
- `CommunityQuotaPolicies.userBlocks` maps user blocks to
  `setCommunityUserBlock`, final writes both private block paths, and uses
  standard App Check token handling.
- `CommunityBlockRepository.blockUser()` and `unblockUser()` still wrote
  directly to `/community_user_blocks` and `/community_blocked_by` before
  Cycle 111.

## Implementation

- Added `CommunityUserBlockInput` and
  `buildCommunityUserBlockCallablePayload()` so Android sends only normalized
  public block target fields, desired state, and block reason when blocking.
- Added `CommunityCallableClient.setCommunityUserBlock()` with `block_` and
  `unblock_` operation IDs.
- Updated `CommunityBlockRepository` so block and unblock:
  - Ensure community source state and identity before selecting a write path.
  - Call `setCommunityUserBlock` first when Firebase Auth has a current UID.
  - Treat `accepted` and `duplicate` callable responses as successful desired
    state.
  - Do not fall back to direct RTDB for quota, Auth, App Check, validation, or
    unexpected callable status failures.
  - Preserve the existing direct RTDB update path only when the callable
    endpoint is missing or Firebase Auth is unavailable.
- Extended `CommunityCallableClientTest` for block and unblock envelopes,
  desired-state payloads, blocker-UID omission, reason inclusion only for
  blocks, and non-limited-use token selection.

## Remaining Risk

- Production enforcement still needs deploy evidence, App Check console
  evidence, full callable wire-protocol coverage, and direct RTDB rule
  tightening.

  confirms the callable endpoint is live for the app's Firebase project.
