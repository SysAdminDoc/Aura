# Cycle 81 - Account Deletion REST Executor

## Scope

Add the guarded operator executor that can dry-run or apply a private account
deletion executor package through the Realtime Database REST API.

## Sources

- Firebase Realtime Database REST save data:
  https://firebase.google.com/docs/database/rest/save-data
- Firebase Realtime Database REST API reference:
  https://firebase.google.com/docs/reference/rest/database
- Firebase Realtime Database REST authentication:
  https://firebase.google.com/docs/database/rest/auth
- Cycle 80 executor package:
  `tools/community_account_deletion_executor_package.py`

## Local Evidence

- Cycle 80 produces a private RTDB null-update package, but no tool can yet
  dry-run the final REST target or execute the package behind explicit
  operator confirmations.
- Firebase REST supports multi-path `PATCH` updates, which matches the planner
  output shape after leading slashes are removed.
- Authenticated REST requests can use an OAuth2 bearer token, which avoids
  adding Python Firebase Admin SDK dependencies to this repo.

## Implementation

- Added `tools/community_account_deletion_rest_executor.py`.
- The executor validates the private package, converts absolute update paths to
  REST multi-path payload keys, and defaults to `--mode dry-run` without
  contacting Firebase.
- Apply mode requires `--confirm-request-code`, `--confirm-plan-hash`, a
  Realtime Database URL, and an OAuth2 token from `--access-token` or
  `FIREBASE_DATABASE_ACCESS_TOKEN`.
- Non-HTTPS database URLs are rejected except for localhost emulator hosts.
- Added `test/tools/community_account_deletion_rest_executor_test.py` covering
  dry-run no-network behavior, confirmation failures, endpoint validation,
  patch payload conversion, and mocked apply `PATCH` requests with bearer auth.
- Wired the executor into Firebase backend CI change detection.
- Updated support, policy, runbook, roadmap, changelog, completed ledger, and
  loop state docs.
