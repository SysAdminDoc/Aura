# Cycle 125 Research - Provider Credential Release Guard

## Goal

Prevent public release builds from silently bundling optional provider
credentials from ignored `local.properties` into `BuildConfig`.

## Local Evidence

- `app/build.gradle.kts` reads `pexels.api.key`, `pixabay.api.key`,
  `freesound.api.key`, `soundcloud.client.id`, and `stability.ai.key` from
  `local.properties` into `BuildConfig` string fields.
- The release workflow writes those optional provider properties as blank values
  before running `:app:assembleRelease`.
- The roadmap already tracks this as the P0 provider credential release guard;
  this pass adds the reusable preflight and CI/release wiring.

## Implementation

- Added `tools/provider_credential_release_check.py` to validate that Gradle
  provider `BuildConfig` fields default to blank local properties, release
  workflow `local.properties` writes blank provider keys, and any explicitly
  checked local properties file has no nonblank provider keys.
- Added `test/tools/provider_credential_release_check_test.py` coverage for
  the live Gradle/workflow policy, nonblank local provider key rejection,
  explicit internal override warning, missing blank release workflow assignment,
  and nonblank `BuildConfig` default drift.
- Wired `.github/workflows/verify.yml` to run the guard before Android setup.
- Wired `.github/workflows/release.yml` to run the guard after writing release
  `local.properties` and before `:app:assembleRelease`.
- Added the provider guard command to
  `docs/distribution/github-security-workflows.json` so the release workflow
  policy fails if the step is removed.
- Updated release signing, release dry-run, supply-chain, roadmap, changelog,
  completion, and loop-state docs.

## Remaining Risk

- This pass does not run a full signed APK build or APK `strings` scan because
  repeated release builds are memory-heavy on this Windows workstation. The
  release workflow now runs the guard before `:app:assembleRelease`.
- The separate user-entered provider key storage and diagnostics redaction
  roadmap items remain open.
