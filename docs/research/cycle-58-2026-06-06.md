# Cycle 58 - Realtime Database Rules Harness

## Scope

Cycle 58 adds Realtime Database emulator coverage for Aura's community backend
rules and fixes the collection-share rules path to match the app's
`CollectionExporter` implementation. It also makes `database.rules.json`
deploy-compatible by removing pseudo-comment fields and replacing unsupported
Realtime Database regex syntax with supported string methods or equality checks.

## Primary Sources

- Firebase Realtime Database Security Rules: https://firebase.google.com/docs/database/security
- Realtime Database rules API: https://firebase.google.com/docs/reference/security/database
- Realtime Database rules regex reference: https://firebase.google.com/docs/reference/security/database/regex
- Firebase Security Rules unit testing: https://firebase.google.com/docs/rules/unit-tests
- Emulator Suite rules-unit-testing reference: https://firebase.google.com/docs/reference/emulator-suite/rules-unit-testing/rules-unit-testing

## Local Evidence

- Cycle 16 found that `CollectionExporter` reads and writes
  `shared_collections/{token}/payload`, while tracked rules granted access under
  `collection_shares/{token}`.
- Cycle 55 added `storagePath` metadata and private `/owner_uploads/{uid}`
  indexes for sound and wallpaper uploads.
- Cycle 57 added the project-local Firebase rules harness and Storage emulator
  coverage, leaving RTDB rules untested.
- The first RTDB emulator run rejected the inherited `database.rules.json`
  because top-level and inline `_comment` properties are not valid deployable
  rule nodes.
- The second RTDB emulator run rejected inherited regexes that used JavaScript
  anchors and `\s`; the rules now use equality checks and documented RTDB string
  methods such as `beginsWith()`.

## Implementation

- Added a Database emulator port to `firebase.json`.
- Added `test:database-rules` and `test:firebase-rules` npm scripts.
- Added `test/firebase/database.rules.test.mjs` with coverage for:
  - community sound metadata public reads, authenticated owner creates,
    cross-owner rejection, bad storage paths, owner deletes, and admin deletes;
  - community wallpaper metadata owner and path enforcement;
  - private owner upload indexes for owners/admins only;
  - report creation, reporter UID validation, admin-only reads, and admin
    status updates;
  - admin-only report resolution receipts;
  - admin-only quota and dedupe ledgers; and
  - `shared_collections` public reads/authenticated creates plus denial for the
    old `collection_shares` path.
- Updated `CollectionExporter` to write `createdByUid` on published share
  records.
- Updated `database.rules.json` so `shared_collections/{token}` is the tracked
  collection-share path. New writes require authentication and matching
  `createdByUid`, public reads remain allowed, owner/admin cleanup is allowed,
  non-owner overwrites are blocked, and payloads are bounded to 512 KiB.
- Added Firebase emulator debug logs to `.gitignore`.
