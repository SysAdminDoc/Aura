# Cycle 109 Research - Android Vote Callable Migration

## Goal

Move Android vote writes from direct Realtime Database first-write behavior to
the existing `recordCommunityVote` callable when Firebase Auth is available,
without claiming production enforcement before deploy evidence, wire-protocol
coverage, and rule tightening are complete.

## Local Evidence

- `functions/src/voteHandler.ts` accepts an envelope with `operationId`,
  `clientSentAt`, and `payload.contentId`, derives `uid` from Firebase Auth,
  requires App Check, normalizes the content ID, checks existing nested and
  legacy voter markers, reserves quota, commits the vote tally, mirrors the
  legacy voter marker, and writes the dedupe marker.
- `CommunityQuotaPolicies.votes` maps votes to `recordCommunityVote`, final
  writes `/votes/{contentId}` and `/voters/{contentId}/{uid}`, and standard App
  Check token use.
- `VoteRepository.upvote()` was still doing a direct RTDB transaction before
  Cycle 109, including nested and legacy voter marker writes.
- Cycle 108 introduced the shared `CommunityCallableClient`, invoker, request
  envelope, and report migration pattern that this cycle can reuse.

## Implementation

- Added `CommunityVoteInput` plus `buildCommunityVoteCallablePayload()` so the
  Android vote request sends only the normalized `contentId`.
- Added `CommunityCallableClient.recordCommunityVote()` with `vote_` operation
  IDs and `CommunityQuotaPolicies.votes.callable` token selection.
- Updated `VoteRepository.upvote()` to:
  - Ensure the community identity is signed in before choosing the write path.
  - Skip duplicate votes already visible through nested or legacy marker reads.
  - Call `recordCommunityVote` first when Firebase Auth has a current UID.
  - Return false for callable duplicate or non-missing callable failures, so
    quota, Auth, App Check, or validation errors do not bypass to direct RTDB.
  - Fall back to the existing direct RTDB transaction only when the callable
    endpoint is missing or Firebase Auth is unavailable.
- Extended `CommunityCallableClientTest` for the vote envelope, normalized
  content ID, and non-limited-use token selection.

## Remaining Risk

- Production enforcement still needs deploy evidence, App Check console
  evidence, full callable wire-protocol coverage, and direct RTDB rule
  tightening.
- Follow, user block, upload finalizer, and profile edit Android repository
  writes still need callable-first adapters.
- The compatibility direct path must stay until owner-approved deploy evidence
  confirms the callable endpoint is live for the app's Firebase project.
