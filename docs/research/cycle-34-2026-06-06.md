# Cycle 34 - Generated Notice Search and High-Risk Alignment

Date: 2026-06-06

## Objective

Make the in-app generated dependency notice viewer usable for repeated review
by adding filtering and surfacing rows that map to curated high-risk dependency
review entries.

## Local Evidence

- The generated release metadata currently contains 288 notice rows.
- The generated metadata names include curated review surfaces such as Firebase,
  Play services, NewPipeExtractor, and youtubedl-android rows.
- `docs/legal/dependency-notice-overrides.json` and
  `docs/legal/dependency-license-policy.json` already encode curated release
  review expectations for high-risk dependency families and native payloads.
- Cycle 33 made generated rows visible in-app, but the list had no filtering and
  no quick path to review-relevant rows.

## Implementation

Updated `GeneratedDependencyNotices.kt`:

- Added a `reviewLabel` field to generated notice rows.
- Added curated review markers for generated rows matching Firebase, Play
  services, ML Kit, NewPipeExtractor, youtubedl-android, ProfileInstaller, and
  ZXing names.
- Added a pure `filter()` helper that matches dependency names, inferred license
  labels, and review labels.

Updated `LicensesScreen.kt`:

- Added a compact filter field for generated notices.
- Added a `Review Watchlist` subsection for matching curated review surfaces.
- Added an `All Generated Notices` subsection that respects the filter.
- Added an empty state for no-match filters.
- Displays review labels on matching generated notice cards.

Updated `LicensesScreenTest`:

- Added filter coverage for dependency names and license labels.
- Added review-marker coverage for Firebase and NewPipeExtractor rows.
- Kept parser and release artifact link coverage intact.

## Result

Cycle 34 makes the generated notice viewer searchable and adds review markers
for generated rows that map to curated high-risk dependency surfaces.

## Remaining Risk

The Kotlin parser and Python lockfile now both depend on the Google OSS metadata
shape, but there is no shared CI guard that proves raw metadata row counts and
range validity stay aligned with `docs/legal/dependency-notices.lock.json`.

## Next Cycle

Start Cycle 35 with a generated notice metadata parity guard.
