# Cycle 124 Research - Always-On Backend Tool Tests

## Goal

Make the lightweight Python backend/tool unit tests part of the always-on
verify workflow so policy checker changes are tested even when they do not
touch Firebase rules paths.

## Local Evidence

- `.github/workflows/verify.yml` runs the workflow, Dependabot, Gradle wrapper,
  callable, notice, native, overlay, and license policy checks directly in the
  always-on verify job.
- The `test/tools` unit suite was only run by the path-gated `firebase-rules`
  job, which means a future checker-only edit could run the checker CLI but
  skip its focused drift tests unless `test/tools` or Firebase paths changed.
- The current backend/tool suite is small: Cycle 123 ran 129 tests in less than
  a second locally.

## Implementation

- Added a `Backend tool unit tests` step to `.github/workflows/verify.yml`
  before Android setup.
- The step runs `python3 -m unittest discover -s test/tools -p '*_test.py'`
  unconditionally on push, pull request, and manual verify runs.
- Updated `docs/distribution/supply-chain.md`, `ROADMAP.md`, `COMPLETED.md`,
  `CHANGELOG.md`, and loop state with the always-on test lane.

## Remaining Risk

- This does not replace Android unit tests, lint, Firebase rules emulator
  coverage, or Functions emulator coverage. It only guarantees the Python
  tool/test suite runs on every verify workflow invocation.
