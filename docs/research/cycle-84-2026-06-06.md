# Cycle 84 - Account Deletion Local/Auth Cleanup Sequence

## Scope

Add the post-backend cleanup sequencing artifact that starts only after a
completed account deletion receipt and orders requester local cleanup, Firebase
Auth deletion, and public upload deletion handoff.

## Sources

- Firebase Auth delete users:
  https://firebase.google.com/docs/auth/android/manage-users#delete_a_user
- Account deletion completion receipt:
  `tools/community_account_deletion_completion_receipt.py`
- Account deletion policy:
  `docs/community-account-deletion-policy.md`

## Local Evidence

- Cycle 82 creates a requester-facing completion receipt after reviewed RTDB
  marker deletion, but local device state, Firebase Authentication deletion, and
  public upload deletion still need a separate order of operations.
- Deleting Firebase Auth before backend marker deletion could make private
  UID-based evidence harder to verify, so Auth cleanup must remain after
  backend completion and owner/operator approval.
- Aura should not imply that clearing local app data deletes public uploads or
  moderation records.

## Implementation

- Added `tools/community_account_deletion_cleanup_sequence.py`.
- The tool validates a completed account deletion completion receipt, requires a
  matching support reference, and rejects non-completed or malformed receipts.
- The generated sequence includes the backend completion hash, request code,
  support reference, redacted UID suffix, marker-delete count, and three ordered
  steps: requester local app cleanup, operator Firebase Auth deletion, and
  separate public upload deletion workflow.
- Added `test/tools/community_account_deletion_cleanup_sequence_test.py`
  covering completion gating, support-reference matching, marker-count
  validation, and redaction.
- Wired the cleanup sequence tool into Firebase backend CI change detection.
- Updated support, policy, runbook, roadmap, changelog, completed ledger, and
  loop state docs.
