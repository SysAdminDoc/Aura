# Cycle 98 - Community Sound Upload Callable Handler

## Goal

Implement the next handler-backed callable write surface by moving sound upload
metadata finalization out of direct client-owned RTDB writes and into a
server-owned Cloud Functions handler core.

## Research

- `UploadRepository.uploadSound()` currently uploads bytes to Storage under
  `sounds/{uid}/{timestamp}_{name}.{extension}`, then writes public metadata to
  `/community_sounds/{uploadId}` and an owner index to
  `/owner_uploads/{uid}/sounds/{uploadId}`.
- `CommunityUploadOwnership.kt` defines the owner-index payload shape:
  `uploadId`, `publicId`, `contentType`, `metadataPath`, `storagePath`, `title`,
  and `createdAt`.
- `CommunityUploadRights.kt` restricts community uploads to `CC0`, `CC BY`, or
  `CC BY-NC`, requires rights attestation, and permits only HTTPS source URLs.
- `database.rules.json` validates sound upload categories, owner index shape,
  selected license, rights attestation, attestation timestamp, optional HTTPS
  source URL, and Storage paths beginning with `sounds/`.
- `storage.rules` already restricts sound blob creation to the authenticated
  owner path and a 20 MB audio MIME allowlist, so the callable can validate the
  metadata ownership boundary without taking over byte upload progress.

## Implementation

- Added `functions/src/soundUploadHandler.ts`.
- Switched `finalizeCommunitySoundUpload` from the fail-closed scaffold to
  `createFinalizeCommunitySoundUploadCallable()`.
- The handler now:
  - requires Firebase Auth and App Check through the shared identity guard;
  - validates the common envelope (`operationId`, `clientSentAt`, `payload`);
  - rejects client-supplied owner, uploader, upload ID, timestamp, and vote
    fields;
  - normalizes sound name, category, tags, MIME type, original filename,
    uploader label, license, rights attestation, download URL, and source URL;
  - requires the Storage path to be exactly under
    `sounds/{authenticatedUid}/...` after the same owner-segment normalization
    used by the Android upload path;
  - derives a hashed dedupe key from the normalized Storage path;
  - reserves UTC quota through the shared quota engine;
  - allocates the public upload ID server-side; and
  - writes `/community_sounds/{uploadId}`,
    `/owner_uploads/{uid}/sounds/{uploadId}`, and the server-owned dedupe
    marker in one backend commit.
- Added `functions/test/finalizeCommunitySoundUpload.test.cjs` for accepted
  finalization, active storage-path dedupe, cooldown, daily-limit,
  unauthenticated, missing-App-Check, and invalid ownership/payload paths.
- Refreshed `docs/community-backend-manifest.json`.
- Updated callable, quota, backend runbook, roadmap, changelog, completed log,
  and loop state docs.

## Remaining Risk

The sound upload finalizer has focused Functions unit coverage, not a live
Emulator Suite callable invocation through the Firebase protocol. Android still
writes sound upload metadata directly after Storage upload, and production
reliance still needs emulator coverage, Android callable migration,
owner-approved deploy evidence, Firebase Console App Check evidence, and direct
RTDB rule tightening.
