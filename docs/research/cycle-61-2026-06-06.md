# Cycle 61 - Admin Upload Delete Actions

## Scope

Cycle 61 adds an admin delete path for rights-confirmed community sound and
wallpaper reports that already have current `storagePath` deletion handles.

## Implementation

- Added `CommunityReportRepository.deleteReportedCommunityUpload()`.
- The method resolves the same rights/community upload target as the Cycle 60
  receipt path, writes a `DELETE` receipt with `deleteState = STARTED`, hides
  the content ID through `/moderation/{contentId}`, deletes the Storage object,
  removes public upload metadata plus the private owner-index row, and marks the
  receipt `SUCCEEDED`.
- If Storage or metadata deletion fails, the receipt is marked `FAILED` with a
  bounded failure stage, message, and timestamp so the handle evidence remains
  available for retry.
- Updated `database.rules.json` so initial takedown receipts must match current
  upload metadata, while later delete-state updates can survive metadata
  removal after the initial receipt exists.
- Added an admin `Delete upload` action to the community report card for
  `RIGHTS` reports on community sounds or wallpapers, with a confirmation
  dialog before deletion starts.
- Added ViewModel coverage for the delete action and RTDB emulator coverage for
  delete receipt state transitions.
