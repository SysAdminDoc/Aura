# Cycle 54 - Community Quota and Rate-Limit Design

## Scope

Cycle 54 defines the quota policy contract for Aura community writes and reserves
protected backend namespaces for quota counters and dedupe markers. This is the
design and guardrail slice; App-Checked callable functions, Storage rules, and
Firebase Console enforcement remain follow-up implementation work.

## Primary Sources

- Firebase App Check metrics: https://firebase.google.com/docs/app-check/monitor-metrics
- App Check for Cloud Functions: https://firebase.google.com/docs/app-check/cloud-functions
- Cloud Functions callable behavior: https://firebase.google.com/docs/functions/callable
- Realtime Database Security Rules: https://firebase.google.com/docs/database/security
- Realtime Database rules API: https://firebase.google.com/docs/reference/security/database
- Cloud Storage Security Rules: https://firebase.google.com/docs/storage/security

## Local Evidence

- `database.rules.json` currently authenticates report, upload, vote, follow, and
  profile writes but does not constrain per-UID write volume.
- `VoteRepository.upvote()` already uses a transaction and per-content voter
  marker, but it does not cap unique daily votes.
- `CommunityReportRepository.submitReport()`, `UploadRepository.uploadSound()`,
  `WallpaperUploadRepository.uploadWallpaper()`, and
  `CreatorProfileRepository.followCreator()` write directly to RTDB paths after
  Firebase Auth.
- Cycle 53 installed App Check providers, but App Check only proves the request
  came from an authorized app install; it does not limit a legitimate client.

## Implementation

- Added `CommunityQuotaPolicy.kt` with typed policy rows for reports, sound
  uploads, wallpaper uploads, votes, follows, and profile edits.
- Added `CommunityQuotaPolicyTest.kt` so new community write surfaces fail tests
  unless they have a quota row, protected ledger path, dedupe key, cooldown, and
  App-Checked callable enforcement target.
- Reserved `/community_write_quotas` and `/community_write_dedupe` in
  `database.rules.json` as admin-only namespaces so modified clients cannot fake
  backend quota counters.
- Added `docs/community-quota-rate-limits.md` with the policy matrix, protected
  ledger schema, rollout order, and verification plan.
- Linked the quota design from the App Check rollout, community reporting, and
  Firebase admin-claims docs.
