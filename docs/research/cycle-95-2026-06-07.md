# Cycle 95 - Community Vote Callable Handler

## Goal

Implement the next handler-backed Cloud Functions write surface from the Cycle
63/91 callable quota contract without adding Android dependency churn or
claiming production enforcement before emulator/deploy evidence exists.

## Research

- `VoteRepository.upvote()` currently writes `/votes/{contentId}/upvotes`,
  nested `/votes/{contentId}/voters/{uid}`, and legacy
  `/voters/{contentId}/{uid}` markers through a Realtime Database transaction.
- Android sanitizes vote keys by replacing Firebase-prohibited key characters
  with underscores; the callable must keep the same stored key shape so existing
  community IDs, top-voted feeds, and account-deletion tooling remain aligned.
- `database.rules.json` still allows authenticated direct vote writes while the
  callable migration is staged, so this cycle cannot claim direct RTDB rules are
  tightened.
- The Cycle 91 contract marks `recordCommunityVote` as App-Checked/Auth-backed
  without limited-use App Check token consumption because votes are a
  higher-volume interaction than reports or upload finalizers.

## Implementation

- Added `functions/src/voteHandler.ts`.
- Switched `recordCommunityVote` from the fail-closed scaffold to
  `createRecordCommunityVoteCallable()`.
- The handler now:
  - requires Firebase Auth and App Check through the shared identity guard;
  - validates the common envelope (`operationId`, `clientSentAt`, `payload`);
  - normalizes the `contentId` to the Android/Firebase key storage form;
  - checks existing nested and legacy voter markers before reserving quota;
  - reads the server-owned dedupe marker;
  - reserves UTC quota through the shared quota engine;
  - returns idempotent duplicates before rewriting public state; and
  - commits the vote tally transaction, nested voter marker, legacy voter
    marker, and dedupe marker through the backend adapter.
- Added `functions/test/recordCommunityVote.test.cjs` for accepted,
  existing-voter duplicate, active-dedupe duplicate, cooldown, daily-limit,
  unauthenticated, missing-App-Check, and invalid-content-ID paths.
- Refreshed `docs/community-backend-manifest.json` and updated callable,
  quota, backend runbook, roadmap, changelog, completed log, and loop state
  docs.

## Remaining Risk

The vote handler has focused Functions unit coverage, not a live Emulator Suite
callable invocation through the Firebase protocol. Android still writes votes
directly to RTDB, and production reliance still needs emulator coverage,
Android callable migration, owner-approved deploy evidence, Firebase Console
App Check evidence, and direct RTDB rule tightening.
