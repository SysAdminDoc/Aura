# Cycle 150 research - store asset pipeline gate

## Question

Owner-gated live backend evidence and signed release dry-run evidence remain
unavailable locally. The next shippable store-readiness gap was the screenshot
and feature-graphic pipeline: Aura had text metadata checks and an optional
asset-mode validator, but no checked capture plan for the missing image assets.

## Sources

- Google Play preview assets: https://support.google.com/googleplay/android-developer/answer/9866151
- F-Droid descriptions, graphics, and screenshots: https://f-droid.org/en/docs/All_About_Descriptions_Graphics_and_Screenshots/
- fastlane supply metadata docs: https://docs.fastlane.tools/actions/supply/

## Findings

- Google Play requires a 512x512 app icon, 1024x500 feature graphic, and at
  least two screenshots, with four phone screenshots recommended for app
  recommendation surfaces.
- Google Play screenshots and feature graphics must be JPEG or 24-bit PNG
  without alpha. Screenshots must depict actual in-app UI and avoid device
  frames, store badges, third-party trademarks, ranking claims, price/sale
  language, and call-to-action wording.
- F-Droid consumes Fastlane-style metadata and image folders, so the same
  `fastlane/metadata/android/en-US/images` structure is the right long-term
  target for both Play and alternative-store prep.
- Aura still lacks current reviewed Fastlane screenshots and a feature graphic,
  so enabling `tools/store_metadata_preflight.py --require-assets` in release
  CI would fail today. A checked capture-pending contract can still prevent the
  shot list, alt text, dimensions, and future command from drifting.

## Decision

Keep the asset status at `capturePending` until real current screenshots and a
feature graphic are committed. The planned phone screenshot slots are:

- `wallpapers`
- `video-wallpapers`
- `sounds-editor`
- `settings-favorites-community`

When the images land, switch the release gate to:

