# Cycle 97 - Community Block Callable Handler

## Goal

Implement the next handler-backed callable write surface while fixing the
user-block dedupe contract so block and unblock retries cannot block each
other.

## Research

- `CommunityBlockRepository.blockUser()` currently writes both
  `/community_user_blocks/{blockerUid}/{blockedUid}` and
  `/community_blocked_by/{blockedUid}/{blockerUid}` through a multi-location
  RTDB update.
- `CommunityBlockRepository.unblockUser()` removes the same two paths.
- `CommunityBlockPolicy.kt` sanitizes both owner keys, rejects self-blocks, and
  stores `blockerUid`, `blockedUid`, `createdAt`, and `reason` in both rows.
- The Cycle 91 callable contract named `setCommunityUserBlock`, but its
  original `blockedUid` dedupe key was too broad for a setter because an active
  block dedupe marker could make an immediate unblock look like a duplicate.

## Implementation

- Refined the user-block quota contract from `blockedUid` to
  `blockedUid + desired state` in the Android policy table, backend JSON
  manifest, Functions contract mirror, validator expectations, and quota
  runbook.
- Added `functions/src/blockHandler.ts`.
- Switched `setCommunityUserBlock` from the fail-closed scaffold to
  `createSetCommunityUserBlockCallable()`.
- The handler now:
  - requires Firebase Auth and App Check through the shared identity guard;
  - rejects client-supplied blocker UID overrides;
  - validates the common envelope (`operationId`, `clientSentAt`, `payload`);
  - normalizes blocker UID, blocked UID, desired block state, and reason;
  - rejects self-block/self-unblock requests after path-key normalization;
  - returns duplicate no-op results before quota reservation when the current
    block state already matches the requested state;
  - uses action-specific dedupe keys for block and unblock requests;
  - reserves UTC quota through the shared quota engine; and
  - sets or removes both private block and admin reverse-index rows plus a
    server-owned dedupe marker.
- Added `functions/test/setCommunityUserBlock.test.cjs` for accepted block,
  accepted unblock, no-op duplicates, same-state dedupe, cooldown, daily-limit,
  unauthenticated, missing-App-Check, and invalid payload paths.
- Refreshed `docs/community-backend-manifest.json` and updated callable,
  quota, block policy, backend runbook, roadmap, changelog, completed log, and
  loop state docs.

## Remaining Risk

The block handler has focused Functions unit coverage, not a live Emulator
Suite callable invocation through the Firebase protocol. Android still writes
block rows directly to RTDB, and production reliance still needs emulator
coverage, Android callable migration, owner-approved deploy evidence, Firebase
Console App Check evidence, and direct RTDB rule tightening.
