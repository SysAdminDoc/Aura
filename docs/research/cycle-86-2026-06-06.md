# Cycle 86 - Account Deletion Auth Package

## Scope

Add the private Firebase Authentication deletion package that can be built only
after request-code lookup and backend deletion completion evidence agree.

## Sources

- Firebase Auth delete users:
  https://firebase.google.com/docs/auth/android/manage-users#delete_a_user
- Account deletion completion receipt:
  `tools/community_account_deletion_completion_receipt.py`
- Account deletion cleanup sequence:
  `tools/community_account_deletion_cleanup_sequence.py`
- Request-code lookup:
  `tools/community_deletion_request_lookup.py`

## Local Evidence

- Cycle 84 orders Auth deletion after backend marker deletion, but there was no
  private package that ties the full UID back to the completed backend deletion
  receipt.
- The existing completion receipt is requester-safe and intentionally omits the
  full UID, so Auth deletion needs a separate private artifact.
- Deleting Auth users must remain owner/operator gated until production project
  access and command evidence are confirmed.

## Implementation

- Added `tools/community_account_deletion_auth_package.py`.
- The package builder validates the request-code lookup, requires exactly one
  lookup match, validates the completed backend receipt through the cleanup
  sequence gate, checks the support reference, and verifies that the private UID
  derives the requested `AURA-` code.
- The private package includes the full UID, safe UID, UID hash, redacted suffix,
  completion receipt hash, lookup evidence hash, operator, and execution
  warning.
- Added `test/tools/community_account_deletion_auth_package_test.py` covering
  the happy path, backend-completion gating, completion request-code mismatch,
  and UID/code mismatch rejection.
- Wired the Auth package tool into Firebase backend CI change detection.
- Updated support, policy, runbook, roadmap, changelog, completed ledger, and
  loop state docs.
