# Cycle 114 Research - Android Profile Edit Callable Migration

## Goal

Move Android creator profile saves onto the existing `updateCreatorProfile`
callable when Firebase Auth is available, while preserving a compatibility
direct RTDB path until owner-approved callable deploy evidence exists.

## Local Evidence

- `functions/src/profileHandler.ts` accepts an envelope with `operationId`,
  `clientSentAt`, and public profile payload fields `displayName`, `bio`,
  `websiteUrl`, and `avatarUrl`.
- The backend derives profile UID from Firebase Auth, rejects UID and timestamp
  overrides, normalizes public profile copy, validates optional HTTPS URLs,
  preserves `createdAt`, assigns `updatedAt`, checks quota, records dedupe, and
  writes `/creator_profiles/{uid}`.
- `CommunityQuotaPolicies.profileEdits` maps profile edits to
  `updateCreatorProfile`, final write path `/creator_profiles/{uid}`, and
  standard App Check token usage.
- `CreatorProfileRepository` already had callable-backed follow/unfollow
  methods, but no editable creator profile path was exposed in Android before
  Cycle 114.

## Implementation

- Added `CreatorProfileUpdateInput` and
  `buildCreatorProfileUpdateCallablePayload()` so Android sends only normalized
  public profile fields and omits server-owned UID and timestamp fields.
- Added `CommunityCallableClient.updateCreatorProfile()` with
  `profile_update_` operation IDs and standard App Check token selection.
- Added `CreatorProfileRepository.updateCreatorProfile()` with callable-first
  saves when Firebase Auth is available, direct RTDB fallback only for missing
  callable endpoint or missing Auth compatibility, and current-profile reads
  for the creator dashboard.
- Added an edit action to `CreatorProfileScreen` that saves display name, bio,
  website URL, and avatar URL through the repository and updates local dashboard
  state after a successful save.
- Extended focused tests for the profile callable envelope and creator profile
  ViewModel state update.

## Remaining Risk

- Production enforcement still needs deploy evidence, App Check console
  evidence, full callable wire-protocol coverage, and direct RTDB rule
  tightening.
- The compatibility direct path must stay until owner-approved deploy evidence
  confirms the callable endpoint is live for the app's Firebase project.
- Profile avatar URL is saved as metadata only; the UI does not yet render
  remote avatar images in the creator summary.
