# Cycle 155 research - background diagnostics support section

## Goal

Continue the background-work diagnostics track by adding a redacted support
bundle section that helps support triage scheduled work without needing a live
device, while keeping direct WorkInfo and Data Saver receipts clearly pending.

## Local evidence

- `CrashDiagnosticsCollector` already builds the local-only diagnostics bundle
  from app/device/source context, scheduler source, crash summary, reproduction
  prompts, and sanitized crash log tail.
- `PreferencesManager` exposes the local settings needed to infer current
  background-work intent: auto wallpaper, enhanced scheduler, Wi-Fi-only,
  charging, idle, unlock rotation, screen-off rotation, and weather effects.
- `SettingsScreen` stores the daily wallpaper toggle in
  `freevibe_weather_wp` as `daily_wallpaper_enabled`.
- The current scheduled work rows remain `auto_wallpaper`, `daily_wallpaper`,
  `weather_update`, `aura_originals_download`, and
  `rotation_trigger_oneshot`.

## Source-backed Android notes

- WorkManager exposes unique-work status lookups through
  `getWorkInfosForUniqueWork`, plus observable LiveData/Flow variants for work
  chains named by a unique work name.
- Android Data Saver diagnostics should use `ConnectivityManager` APIs for
  active metered-network status and restricted-background status.
- A support bundle can safely record local settings and expected constraints,
  but live scheduler state should come from WorkManager `WorkInfo` so the app
  does not present inferred state as actual execution state.

## Implementation decision

Added a background-work section to the local diagnostics bundle. The section
lists each unique work name, inferred enabled state, network posture, expected
constraints, and explicit pending markers for live WorkInfo and Data Saver
receipts. This closes the support-bundle half of the Cycle 14 acceptance
without claiming last-run or live scheduler state.

## Remaining work

- Add a Settings diagnostics surface that reads WorkManager status for each
  unique work name.
- Add direct `ConnectivityManager` Data Saver and active metered-network
  receipts.
- Persist last success/failure/error receipts from worker execution so support
  can distinguish "scheduled but deferred" from "ran and failed."
- Add user-facing deferral text for quota downgrade, no network, metered-only
  restrictions, low battery, and missing notification/location permission.
