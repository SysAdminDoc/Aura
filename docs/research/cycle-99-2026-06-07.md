# Cycle 99 - Community Wallpaper Upload Callable Handler

## Goal

Implement the next handler-backed callable write surface by moving wallpaper
upload metadata finalization out of direct client-owned RTDB writes and into a
server-owned Cloud Functions handler core.

## Research

- `WallpaperUploadRepository.uploadWallpaper()` currently compresses uploads to
  JPEG, writes bytes to Storage under
  `wallpapers/{uid}/{timestamp}_{name}.jpg`, then writes public metadata to
  `/community_wallpapers/{uploadId}` and an owner index to
  `/owner_uploads/{uid}/wallpapers/{uploadId}`.
- The public metadata includes `name`, `category`, `tags`, `colors`,
  `thumbnailUrl`, `fullUrl`, `downloadUrl`, `storagePath`, `width`, `height`,
  `fileSize`, `fileType`, `originalFileName`, uploader fields, license fields,
  rights attestation fields, optional source URL, and `votes`.
- `CommunityUploadOwnership.kt` defines the wallpaper owner-index payload shape:
  `uploadId`, `publicId`, `contentType`, `metadataPath`, `storagePath`, `title`,
  and `createdAt`, with `cw_` public IDs.
- `database.rules.json` validates wallpaper upload categories, owner index
  shape, selected license, rights attestation, attestation timestamp, optional
  HTTPS source URL, and Storage paths beginning with `wallpapers/`.
- `storage.rules` already restricts wallpaper blob creation to the
  authenticated owner path and JPEG payloads under 4 MB, so the callable can own
  metadata finalization while the Android client keeps byte-upload progress.

## Implementation

- Added `functions/src/wallpaperUploadHandler.ts`.
- Switched `finalizeCommunityWallpaperUpload` from the fail-closed scaffold to
  `createFinalizeCommunityWallpaperUploadCallable()`.
- The handler now:
  - requires Firebase Auth and App Check through the shared identity guard;
  - validates the common envelope (`operationId`, `clientSentAt`, `payload`);
  - rejects client-supplied owner, uploader, upload ID, timestamp, and vote
    fields;
  - normalizes wallpaper name, category, tags, palette colors, URLs,
    dimensions, file size, MIME type, original filename, uploader label,
    license, rights attestation, and source URL;
  - requires JPEG metadata under the authenticated-owner
    `wallpapers/{uid}/...` Storage path;
  - derives a hashed dedupe key from the normalized Storage path;
  - reserves UTC quota through the shared quota engine;
  - allocates the public upload ID server-side; and
  - writes `/community_wallpapers/{uploadId}`,
    `/owner_uploads/{uid}/wallpapers/{uploadId}`, and the server-owned dedupe
    marker in one backend commit.
- Added `functions/test/finalizeCommunityWallpaperUpload.test.cjs` for accepted
  finalization, active storage-path dedupe, cooldown, daily-limit,
  unauthenticated, missing-App-Check, and invalid ownership/payload paths.
- Refreshed `docs/community-backend-manifest.json`.
- Updated callable, quota, backend runbook, roadmap, changelog, completed log,
  and loop state docs.

## Remaining Risk

The wallpaper upload finalizer has focused Functions unit coverage, not a live
Emulator Suite callable invocation through the Firebase protocol. Android still
writes wallpaper upload metadata directly after Storage upload, and production
reliance still needs emulator coverage, Android callable migration,
owner-approved deploy evidence, Firebase Console App Check evidence, and direct
RTDB rule tightening.
