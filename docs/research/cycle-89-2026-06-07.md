# Cycle 89 - Auth Deletion Execution Receipt

## Scope

Add a redacted receipt gate for owner-approved Firebase Auth deletion evidence
after backend account marker deletion has completed.

## Sources

- Firebase Admin SDK user management and delete user docs:
  https://firebase.google.com/docs/auth/admin/manage-users
- Existing Auth deletion package:
  `tools/community_account_deletion_auth_package.py`
- Account deletion support runbook:
  `docs/support/community-account-deletion.md`

## Local Evidence

- Cycle 86 builds a private Auth deletion package with the full UID after lookup
  and backend completion evidence match.
- The support runbook still only said to archive private command evidence after
  Auth deletion. That left no normalized, redacted receipt proving owner
  approval, post-delete lookup, and evidence hashing without exposing the full
  UID or project identifiers.
- Firebase Auth deletion must remain an owner/admin operation. A local repo tool
  should validate evidence after the action, not perform the production delete.

## Implementation

- Added `tools/community_account_deletion_auth_execution_receipt.py`.
- The receipt builder validates the private Auth package, request code, support
  reference, full UID/UID hash, owner-approved method, execution status,
  post-delete `notFound` verification, private evidence reference, and private
  evidence SHA-256.
- The emitted receipt omits the full Firebase UID, project ID, raw command
  output, service-account credentials, console exports, and tokens.
- Added `validate_auth_execution_receipt()` for future downstream private
  deletion tooling.
- Added `test/tools/community_account_deletion_auth_execution_receipt_test.py`
  for the redacted happy path and UID, support-reference, method, and evidence
  hash rejection cases.
- Wired the tool into Firebase backend CI change detection.
- Updated support, policy, backend runbook, roadmap, changelog, completed
  ledger, and loop state docs.
