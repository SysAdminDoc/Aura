# Cycle 123 Research - GitHub Workflow Secret Guard

## Goal

Make workflow secret usage reviewable and machine-checked so GitHub Actions
edits cannot silently add new repository secrets, unreviewed environment
aliases, or token shortcuts.

## Local Evidence

- Cycle 121 added a workflow action allowlist across all five workflow files.
- Cycle 122 added workflow event and permission baseline checks across all five
  workflow files.
- Source search found eight current `${{ secrets.* }}` references, all in
  `.github/workflows/release.yml` and all tied to the four release signing
  secrets.

## Implementation

- Added `docs/distribution/github-workflow-secrets.json` with the required
  workflow file set, forbidden token shortcuts, and the reviewed release
  signing secret/env-name pairs.
- Added `tools/github_workflow_secrets_check.py` to reject missing or
  unexpected workflow files, unreviewed secret references, unreviewed
  environment aliases, forbidden token patterns, non-env secret expressions,
  and unused policy entries.
- Added `test/tools/github_workflow_secrets_check_test.py` coverage for the
  live workflow set and drift cases around unreviewed secrets, forbidden token
  references, alias drift, missing workflows, and unused policy entries.
- Wired `.github/workflows/verify.yml` so the secret policy check runs before
  Android setup.
- Updated `docs/distribution/supply-chain.md`, `ROADMAP.md`, `COMPLETED.md`,
  `CHANGELOG.md`, and loop state with the new guard.

## Remaining Risk

- The guard validates secret references in workflow YAML, not the GitHub
  repository secret settings themselves. Owner/admin live evidence remains
  covered by the separate GitHub security settings receipt.
- Production community callable enforcement and live GitHub repository security
  claims still require owner-provided evidence described in the current
  continuation state.
