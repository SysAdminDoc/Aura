# Cycle 129 - Cleartext release gate and ccMixter HTTPS-only decision

## Objective

Close the release-blocking cleartext posture item from Cycle 15 by making
ccMixter HTTPS-only and adding a machine-checkable release guard.

## Local evidence

- `AndroidManifest.xml` already declares `android:usesCleartextTraffic="false"`
  and references `@xml/network_security_config`.
- `network_security_config.xml` still allowed cleartext for all
  `ccmixter.org` subdomains.
- `CcMixterRepository` retried `SSLException` failures through a direct
  OkHttp `HttpUrl.Builder().scheme("http")` fallback.
- `docs/security/network-endpoints.json` and
  `docs/security/network-endpoints.md` still documented ccMixter as the only
  reviewed cleartext-capable network surface.

## Implementation

- Removed the ccMixter HTTP fallback request path. `CcMixterRepository` now
  calls the Retrofit HTTPS API only; TLS failures propagate through
  `SourceMetrics.measure()` as provider failures.
- Removed the `ccmixter.org` cleartext exception from
  `network_security_config.xml`.
- Replaced the old fallback URL helper test with a regression proving
  `SSLHandshakeException` is not downgraded and is recorded as a ccMixter
  source failure.
- Added `tools/cleartext_release_check.py` to fail release policy when:
  - `network_security_config.xml` contains `cleartextTrafficPermitted="true"`.
  - `AndroidManifest.xml` explicitly enables `usesCleartextTraffic="true"`.
  - provider-network Kotlin/Java roots contain raw `http://` URL literals.
  - provider-network Kotlin/Java roots contain OkHttp `.scheme("http")`
    builders.
- Wired the cleartext guard into `.github/workflows/verify.yml` and
  `.github/workflows/release.yml` before Android build work.
- Added the release workflow guard snippet to
  `docs/distribution/github-security-workflows.json`.
- Updated the network endpoint inventory and supply-chain runbook to record
  ccMixter as HTTPS-only.
