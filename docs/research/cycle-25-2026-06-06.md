## Executive Summary

Cycle 25 adds the native compliance freshness gate that remained open after the native markdown packet and dependency notice lockfile.

Implemented in the real repo:

- `tools/native_compliance_inventory.py` now supports `report`, `write-lock`, and `check-lock` modes.
- `docs/legal/native-compliance.lock.json` records current native/copyleft artifact hashes and extracted payload facts.
- `.github/workflows/verify.yml` checks the native lockfile on PRs, main pushes, and manual verification.
- `.github/workflows/release.yml` checks the native lockfile before generating release notice artifacts.
- `docs/distribution/supply-chain.md` documents native lockfile checks and intentional refresh commands.

The lock catches stale native evidence when youtubedl-android, NewPipeExtractor, yt-dlp, Python, QuickJS, or FFmpeg artifact hashes/payload facts change. It still does not prove FFmpeg configure/source correspondence because that information is not encoded in the resolved AAR.

## Implementation

Native lock mode:

- Reuses the existing Gradle cache coordinate list from the markdown report.
- Hashes `.aar`, `.jar`, `.pom`, and `.module` artifacts.
- Extracts and locks interesting AAR/JAR payload entries.
- Locks nested zip entry counts, selected nested sample entries, and facts extracted from `res/raw/ytdlp` and `libpython.zip.so`.
- Writes `docs/legal/native-compliance.lock.json` with schema version, coordinate records, artifact hashes, payload facts, and counts.
- In check mode, compares current resolved artifacts to the committed lockfile and exits nonzero if artifact hashes, payload facts, or payload entries drift.

Workflow integration:

- `verify.yml`
  - Runs `python3 tools/native_compliance_inventory.py --mode check-lock --lockfile docs/legal/native-compliance.lock.json` after `:app:releaseOssLicensesTask`.
- `release.yml`
  - Runs the same check before generating `THIRD-PARTY-NOTICES.md` and `NATIVE-COMPLIANCE.md`.
