# Cycle 35 - Generated Notice Metadata Parity Guard

Date: 2026-06-06

## Research

Google's current open-source notice guide still presents the Play services OSS
licenses path as a build-time Gradle plugin plus optional runtime SDK. The plugin
processes POM license metadata at compile time and packages license resources
with the app. Aura already uses the plugin-only path so the app can read generated
raw resources without pulling the stock runtime activity and its release-runtime
dependency graph.

## Local Evidence

- `tools/dependency_notice_lock.py` already parses
  `third_party_license_metadata`, validates each offset/length against
  `third_party_licenses`, and locks notice names, offsets, lengths, and notice
  text hashes.
- `GeneratedDependencyNotices.kt` now reads the same raw metadata and license
  text resources at runtime for the in-app Settings notice viewer.
- `docs/legal/dependency-notices.lock.json` currently records 251 dependency
  records and 288 notice sections.

## Decision

Keep the full dependency notice drift check as the broad review gate, and add a
metadata-only parity mode for the narrower in-app viewer assumption. The new mode
reuses the existing parser/range validation, then compares the generated
metadata-derived notice rows against the reviewed lockfile. This gives CI a
focused failure when raw metadata row counts, offsets, lengths, names, or notice
hashes diverge from the reviewed lock.

## Implementation

- Added `--mode check-metadata` to `tools/dependency_notice_lock.py`.
- Wired the metadata parity check into PR/main verification and release builds
  immediately after the full generated notice lock check.
- Documented the local and release verification command in
  `docs/distribution/supply-chain.md`.

## Verification Plan

- Compile the release-compliance Python tools.
- Run the existing generated notice lock check.
- Run the new generated notice metadata parity check against current generated
  outputs.
- Run temporary generated-root negative fixtures with an out-of-range metadata
  row and a missing metadata row, then confirm `check-metadata` fails.
