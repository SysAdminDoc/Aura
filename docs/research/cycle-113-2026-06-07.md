# Cycle 113 Research - Android Wallpaper Upload Finalizer Callable Migration

## Goal

Move Android wallpaper upload metadata finalization from direct Realtime
Database first-write behavior to the existing
`finalizeCommunityWallpaperUpload` callable when Firebase Auth is available.
Storage bytes still upload through Firebase Storage; the callable owns the
public metadata and owner-index write.

## Local Evidence

- `functions/src/wallpaperUploadHandler.ts` accepts an envelope with
  `operationId`, `clientSentAt`, and wallpaper metadata containing `name`,
  `category`, `tags`, `colors`, `thumbnailUrl`, `fullUrl`, `downloadUrl`,
  `storagePath`, `width`, `height`, `fileSize`, `fileType`,
  `originalFileName`, `uploaderLabel`, `license`, `rightsAttested`, and
  optional `sourceUrl`.
- The backend derives uploader UID from Firebase Auth, requires App Check with
  limited-use token consumption, validates Storage path ownership, JPEG
  dimensions and file-size bounds, reserves quota, allocates the upload ID,
  writes `/community_wallpapers/{uploadId}` and
  `/owner_uploads/{uid}/wallpapers/{uploadId}`, and records a storage-path
  dedupe marker.
- `CommunityQuotaPolicies.wallpaperUploads` maps wallpaper uploads to
  `finalizeCommunityWallpaperUpload`, final writes public metadata plus owner
  index rows, and consumes limited-use App Check tokens.
- `WallpaperUploadRepository.uploadWallpaper()` already uploaded compressed
  Storage bytes, fetched the download URL, and then wrote public metadata and
  owner-index rows directly to RTDB before Cycle 113.

## Implementation

- Added `CommunityWallpaperUploadMetadataInput` and
  `buildCommunityWallpaperUploadCallablePayload()` so Android sends only
  normalized finalizer metadata and omits server-owned uploader, timestamp,
  upload ID, public ID, attestation timestamp, and vote fields.
- Added `CommunityCallableClient.finalizeCommunityWallpaperUpload()` with
  `wallpaper_upload_` operation IDs and limited-use App Check token selection.
- Updated `WallpaperUploadRepository.uploadWallpaper()` so the post-Storage
  metadata step:
  - Calls `finalizeCommunityWallpaperUpload` first when Firebase Auth has a
    current UID.
  - Treats `accepted` and `duplicate` callable responses as successful
    finalization.
  - Does not fall back to direct RTDB for quota, Auth, App Check, validation,
    storage ownership, or unexpected callable status failures.
  - Preserves the existing direct RTDB metadata and owner-index write only when
    the callable endpoint is missing or Firebase Auth is unavailable.
  - Keeps failed-finalization cleanup behavior that deletes the uploaded
    Storage object when metadata was not saved.
- Extended `CommunityCallableClientTest` for wallpaper upload finalizer
  envelopes, metadata normalization, server-owned field omission, and
  limited-use token selection.

  tightening.
