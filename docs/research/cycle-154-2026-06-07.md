# Cycle 154 research - background network posture

## Goal

Continue the background-work hardening track by recording which workers may run
on metered networks, which require unmetered network, and where direct Data
Saver diagnostics are still missing.

## Local evidence

- `AutoWallpaperWorker` can use connected network or unmetered network depending
  on the existing Wi-Fi-only setting. It also keeps battery-not-low and optional
  charging/idle constraints.
- `DailyWallpaperWorker` uses connected network, a daily cadence, and the
  Reddit provider switch. Its payload is metadata plus a capped notification
  thumbnail.
- `WeatherUpdateWorker` uses connected network and depends on location
  permission plus last-known location.
- `AuraOriginalsDownloader` uses unmetered network and caps the first-run sound
  pack by per-file and total bytes with SHA-256 verification.
- `RotationTriggerService` one-shots use connected network and battery-not-low
  with expedited fallback.

## Source-backed Android notes

- WorkManager network constraints can require connected or unmetered network;
  the unmetered constraint maps to Wi-Fi or another unmetered connection.
- Android Data Saver state is available from `ConnectivityManager`, including
  metered-network and background restriction status. Aura does not yet expose
  those values in Settings diagnostics.
- `ConnectivityManager.isActiveNetworkMetered()` is the API surface for checking
  whether the active network should avoid large transfers.

## Implementation decision

Added a checked `background-work-network-posture` packet instead of changing
worker behavior. The current behavior is acceptable for release gating because
larger first-run downloads are unmetered-only, auto wallpaper has a user
Wi-Fi-only control, and the remaining connected workers are now explicitly
called out as pending direct Data Saver receipts.

## Remaining work
