# Cycle 131 - Provider Credential APK Scan

## Scope

Cycle 131 closed the remaining code-side gap in the provider credential release guard by adding an APK string scan stage. Owner-provided release-secret dry-run evidence is still an operational release checklist item, but the release workflow now performs the scan whenever it packages a signed APK.

## Local Evidence

- Cycle 125 proved Gradle defaults and release workflow `local.properties` writes are blank for Pexels, Pixabay, Freesound, SoundCloud, and Stability.
- Cycle 130 documented user-entered provider key storage and backup/device-transfer exclusions.
- The remaining roadmap acceptance was a strings/APK scan proving provider credential values do not appear in the distributed release artifact.

## Implementation

- Added `tools/provider_credential_apk_scan.py`.
- Added `test/tools/provider_credential_apk_scan_test.py` with blank release properties, clean nonblank fixtures, embedded sentinel detection, multi-APK detection, missing-file rejection, and no-secret-value error assertions.
- Wired `.github/workflows/release.yml` to run the scanner after the signed APK is packaged and before notice generation, checksums, uploads, or tagged publication.
- Added the scanner command to `docs/distribution/github-security-workflows.json` so release workflow policy validation fails if the scan is removed.
- Updated release signing, release dry-run, supply-chain, roadmap, changelog, completion, and loop-state docs.
