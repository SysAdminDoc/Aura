# Cycle 120 Research - Gradle Wrapper Checksum Guard

## Goal

Pin Aura's Gradle wrapper distribution by SHA-256 and make wrapper drift
checkable in CI.

## Local Evidence

- `gradle/wrapper/gradle-wrapper.properties` already used the Gradle 8.12 bin
  distribution and `validateDistributionUrl=true`.
- The wrapper properties did not include `distributionSha256Sum`, so Gradle
  would validate the distribution URL but not the downloaded ZIP digest.
- The official Gradle checksum endpoint for `gradle-8.12-bin.zip` returned
  `7a00d51fb93147819aab76024feece20b6b84e420694101f276be952e08bef03`.

## Implementation

- Added `distributionSha256Sum` to `gradle/wrapper/gradle-wrapper.properties`
  with the official Gradle 8.12 bin ZIP SHA-256.
- Added `tools/gradle_wrapper_check.py` to validate the reviewed Gradle 8.12
  bin distribution URL, wrapper SHA-256, URL validation, storage roots, and
  network timeout.
- Added `test/tools/gradle_wrapper_check_test.py` coverage for the live wrapper
  and drift cases around missing checksum, checksum drift, `-all` distribution
  drift, disabled URL validation, and low network timeout.
- Wired `.github/workflows/verify.yml` so the wrapper policy check runs before
  Android setup.
- Updated `docs/distribution/supply-chain.md`, `ROADMAP.md`, `COMPLETED.md`,
  `CHANGELOG.md`, and loop state with the new wrapper guard.

## Remaining Risk

- Future Gradle upgrades must update the wrapper URL, SHA-256, wrapper policy
  constant, focused tests, and any related dependency-verification metadata in
  the same reviewed change.
- Production community callable enforcement and live GitHub repository security
  claims still require owner-provided evidence described in the current
  continuation state.
