# Cycle 152 - Rotation trigger foreground-service policy gate

Date: 2026-06-07

## Question

Aura uses `RotationTriggerService` as a `specialUse` foreground service for
opt-in unlock and screen-off wallpaper rotation triggers. Android supports the
`specialUse` type, but the manifest subtype and Play Console declaration need
reviewable evidence before Play production submission.

## Local findings

- `app/src/main/AndroidManifest.xml` declares
  `android.permission.FOREGROUND_SERVICE_SPECIAL_USE`.
- `.service.RotationTriggerService` is exported false and declares
  `android:foregroundServiceType="specialUse"`.
- The service includes
  `android.app.PROPERTY_SPECIAL_USE_FGS_SUBTYPE=wallpaper_rotation_triggers`.
- `RotationTriggerService.kt` starts foreground with
  `ServiceInfo.FOREGROUND_SERVICE_TYPE_SPECIAL_USE` on Android 14 and newer,
  dynamically registers `ACTION_USER_PRESENT` and `ACTION_SCREEN_OFF` with
  `Context.RECEIVER_NOT_EXPORTED`, and enqueues one coalesced
  `AutoWallpaperWorker` request with network and battery constraints.
- Settings exposes explicit opt-in toggles for unlock and screen-off triggers.

## Source-backed decision

Cycle 152 keeps the current runtime design, but makes the policy evidence
checked. The service is still appropriate only while a user has opted into a
trigger. The Play submission remains owner-action-gated until the owner archives
the Play Console foreground-service declaration row, a demo video URL or
internal evidence pointer, and an Android 14+ smoke result.

## Implementation

- Added `docs/rotation-trigger-fgs-policy.md` and
  `docs/rotation-trigger-fgs-policy.json`.
- Added `tools/rotation_fgs_policy_check.py` and focused tests.
- Extended the Play App content packet with a foreground-service declaration
  section, `foregroundServices` JSON row, and
  `capture-foreground-service-declaration-evidence` owner action.
- Corrected the Play packet's current manifest permission count to 14 after
  Cycle 151.
- Wired verify/release workflows, release metadata consistency, GitHub security
  workflow policy, release signing, release dry-run, and supply-chain docs to
  run the new gate.
