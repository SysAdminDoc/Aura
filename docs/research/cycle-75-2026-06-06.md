# Cycle 75 - Community Identity Request Surface

## Scope

Add a user-visible Settings surface for the community identity that supports
the account-deletion request workflow without creating a new Firebase account
only because the user opened Settings.

## Sources

- Google Play account deletion requirements:
  https://support.google.com/googleplay/android-developer/answer/13327111
- Firebase Auth delete users:
  https://firebase.google.com/docs/auth/android/manage-users#delete_a_user
- Firebase Realtime Database delete data:
  https://firebase.google.com/docs/database/android/read-and-write#delete_data
- Cycle 74 deletion policy:
  `docs/community-account-deletion-policy.md`

## Local Evidence

- `CommunityIdentityProvider.ensureSignedIn()` creates a Firebase anonymous
  identity when needed for community writes.
- `SettingsScreen` already owns the Community source controls and the blocked
  creators review surface.
- `SettingsViewModel` already exposes synchronous community moderation and
  block-list state for Settings.
- The Cycle 74 deletion planner needs a user-facing code or redacted identity
  handle before support can safely match a deletion request to backend data.

## Implementation

- Added `CommunityIdentitySummary` plus read-only summary helpers to
  `CommunityIdentityProvider`.
- `currentIdentitySummary()` reads the existing Firebase UID or already-created
  local fallback ID without calling `fallbackId` or `ensureSignedIn()`, so the
  Settings identity panel does not create a local fallback UUID or Firebase
  anonymous account.
- Added a stable redacted identity suffix and an `AURA-` deletion request code
  derived from the Firebase UID hash when a Firebase identity already exists.
- Added `SettingsViewModel.communityIdentitySummary` and a refresh method.
- Added Settings > Community identity with a dialog that shows auth type,
  redacted identity suffix, deletion request code when available, copy action,
  and retained-data policy copy.
- Updated the account deletion policy, roadmap, changelog, completed ledger,
  and loop state.
