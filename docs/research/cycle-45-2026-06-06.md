# Cycle 45 Research: Generated Wallpaper Source Switch

## Goal

Close the generated-content runtime-control gap with a default-on source switch
that can remove generation entry points for store or distribution profiles while
preserving existing saved local generated wallpapers.

## Local Evidence

- `ProviderDisclosure.kt` marked `ContentSource.AI_GENERATED` partial because a
  blank Stability key gated requests, but there was no source-level switch.
- `WallpapersScreen` exposed the Generate chip unconditionally.
- `AiWallpaperScreen` showed the key surface and request button whenever the
  route was opened.
- `AiWallpaperViewModel.generate()` validated prompt and key before calling
  `AiWallpaperRepository.generate()`, so a source-level gate needed to run
  before those checks and before any repository call.

## Decision

Add a `generated_content_provider_enabled` preference that defaults on. When it
is off, hide the Wallpapers Generate chip, hide the generator key surface, and
block generation in the ViewModel before prompt/key validation. Keep saved
generated wallpapers visible because they are local user content rather than a
remote provider feed.

## Implementation Notes

- Added `PreferencesManager.generatedContentProviderEnabled` and a setter.
- Added Settings ViewModel state and an "Enable generated wallpapers" switch.
- Hid the Stability key row while generated wallpapers are disabled.
- Added generated-source state to `WallpapersViewModel` and hid the Generate
  chip in `WallpapersScreen`.
- Added generated-source state, request-gate helper, and disabled diagnostics
  in `AiWallpaperViewModel`.
- Updated `AiWallpaperScreen` so disabled mode hides the key field, disables the
  key button and request button, and never calls `generate()` from the button.
- Updated `ProviderDisclosure.kt` and `docs/legal/provider-runtime-controls.md`
  to mark AI-generated runtime controls covered.

## Verification Plan

- Focused AI wallpaper request-gate tests cover disabled-mode precedence before
  prompt/key validation and enabled-mode validation behavior.
- Settings and Wallpapers ViewModel fixtures include the new default-on
  preference flow.
- Provider disclosure tests verify the runtime-control row remains complete.
- Release-compliance Python checks remain unchanged and should still pass.
