# Cycle 36 - Runtime Provider Kill-Switch Matrix

Date: 2026-06-06

## Research

Provider policies still make runtime disablement a release concern, not just a
settings preference:

- Pexels says its API can enhance a broader product but cannot be the standalone
  wallpaper experience. Aura therefore needs a real Pexels-off state that works
  even when a default key is bundled.
- Pixabay documents attribution, a 100 requests per 60 seconds default limit,
  24-hour request caching, and no systematic mass downloads. Aura needs a
  provider state that distinguishes intentionally disabled from rate-limited or
  temporarily unavailable.
- Reddit's current Data API and Developer Terms require compliance with user
  content restrictions, removals, rate limits, and app review/audit rules. Aura
  should not treat editable subreddit lists as a full kill switch.
- YouTube's current developer policies restrict downloading, caching, storing,
  offline playback, and stale API data. Aura's YouTube paths span catalog search,
  direct URL import, preview/download resolution, and video wallpapers, so a
  legal-mode switch must block more than a tab label.

## Local Evidence

- `ProviderDisclosure.kt` covered policy disclosure rows but had no runtime
  control model.
- `PreferencesManager.kt` exposes optional provider keys and content-safety
  toggles, but no general provider-enabled flags.
- `WallpaperRepository.kt` already short-circuits Pexels/Pixabay when effective
  keys are blank.
- `VideoWallpapersViewModel.kt` attempts Pexels, Reddit, YouTube, and Pixabay in
  one load path; Reddit video subreddits are hardcoded.
- `SoundsViewModel.kt` uses YouTube for default sound tabs, YouTube tab search,
  pasted URL import, similar sounds, top hits, preview resolution, and download
  resolution.

## Decision

Add a checked provider runtime-control matrix before changing feed behavior. This
keeps the audit factual and prevents a partial toggle from being mistaken for a
complete kill switch. Mark missing/partial providers explicitly so the next pass
can implement one source family at a time.

## Implementation

- Added `ProviderRuntimeControl` and `ProviderRuntimeControlStatus` to
  `ProviderDisclosure.kt`.
- Added a runtime-control row for every `ContentSource`.
- Extended `ProviderDisclosureTest` so every source has exactly one runtime
  control row and unresolved rows must carry a concrete follow-up.
- Added `docs/legal/provider-runtime-controls.md` and linked it from
  `docs/legal/provider-policy.md`.

## Verification Plan

- Run the focused provider disclosure unit test.
- Run the lightweight release-compliance Python checks to ensure the previous
  compliance gates still pass.
- Run `git diff --check` and the changed-line attribution scan before commit.
